# PRD: Task 4.4 — Сервис айтемов

## Описание задачи
Реализовать Application/Infrastructure-слой для айтемов: создание, редактирование, получение, удаление и списки, с логикой динамических полей (маппинг `CollectionField`-совместимых слотов в 12 колонок `Item`) и тегов (через `TagService`). Создать отсутствующие `DoctrineItemRepository` и `ItemNotFoundException` (в 4.1 были созданы только entity, `ItemId` и интерфейс репозитория).

Сервис **не флашит** самостоятельно ничего лишнего: теги пишутся атомарно через `getOrCreate` (4.3), Item сохраняется через `save()` + один `UnitOfWork::flush()` в конце операции.

## Ссылки на требования

- `artifacts/domain-model-taskflow-ru.md` — Item (12 слотов), связи Item→Collection, Item↔Tag; «айтем должен иметь владельца» (через коллекцию).

## Решения (согласованы с пользователем)
1. **Валидация слотов — свободная.** Слоты не сверяются со схемой `CollectionField`; любой слот можно не заполнять.
2. **Списки — оба:** `listByCollection` и `listByOwner` (второй требует `ItemRepositoryInterface::findByOwnerId`).
3. **Формат слотов в DTO — массив структур** `{type, slot, value}`.
4. **Фильтры списка — вне 4.4**, но фиксируются в Roadmap как часть задачи 4.5 (API-эндпоинты) — иначе требование PRD (поиск айтемов по имени/тегам) потеряется.
5. **Теги при обновлении — replace:** набор тегов заменяется переданным (лишние `removeTag`, недостающие `addTag`), сравнение по `TagId`.
6. **Слоты при обновлении — частичные:** трогаются только слоты из DTO; `value: null` очищает слот; остальные не меняются.
7. **Даты на входе** — ISO-8601 строка → `DateTimeImmutable`; невалидная → `\InvalidArgumentException`.
8. **Авторизация** (владелец коллекции) сервисом не проверяется — уровень контроллера (4.5).

## Ограничения
- `Item.collection` — `ManyToOne(fetch: LAZY)` на `final Collection`. Все read-методы репозитория **обязаны** делать `JOIN FETCH i.collection`, иначе Doctrine ORM 3 бросает `Cannot generate lazy ghost` (подтверждённый паттерн: review-5, Task 3.4).
- Doctrine — только в Infrastructure. Application не импортирует `Doctrine\*`.
- `UnitOfWorkInterface` не расширяем (`fwd-1` остаётся отложенным).
- Без миграций (схема `items`/`item_tags` из 4.1/4.2).

## Заметки
- **fwd-1** (transactional boundary): `create` не атомарен (Item в flush в конце, теги пишутся сразу через `getOrCreate`). Для MVP терпимо (теги глобальные). Остаётся отложенным.
- **Orphan-теги:** если между `getOrCreate` (теги уже записаны) и финальным `flush` Item возникает ошибка, теги остаются без айтема. Теги глобальные и безвредные; при необходимости 4.5 добавит компенсирующую чистку или транзакционную границу (fwd-1).
- **N+1 по тегам** в списках: `ItemDTO::fromEntity` → `getTags()` на каждый item. Для MVP ок; при росте — `leftJoin('i.tags','t')->addSelect('t')`.
- **fwd-2** (произвольное число слотов): сервис маппинга 4.4 — кандидат на изменение при втягивании fwd-2.
