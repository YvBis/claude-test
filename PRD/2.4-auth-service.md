## Описание задачи

Создать сервис аутентификации (`AuthenticationService`) в Application слое и REST API эндпоинты:

## Ограничения

- **Только Application + Infrastructure (Controller, Security) слои** — никаких изменений в Domain
- **Использовать существующие VO/Entity** — `Email`, `PasswordHash` (метод `verifyPassword()`), `User`, `UserId`, `Role`
- **Использовать `UserRepositoryInterface`** — через DI, не конкретную реализацию
- **JWT токены** — `lexik/jwt-authentication-bundle` (установить)
- **Refresh tokens** — опционально для MVP, можно оставить только Access Token с времением жизни 1 час
- **Firewall настройка** — `json_login` для `/api/login`, `stateless: true`, provider от Doctrine User entity
- **Logout** — для stateless JWT достаточно клиентского удаления токена; серверная blacklist — out of scope для MVP
- **Валидация DTO** — Symfony Validator constraints
- **OpenAPI документация** — атрибуты `#[OA\Post]`, `#[OA\RequestBody]`, `#[OA\Response]`

## Domain Exceptions

Создать в `src/Domain/User/Exception/`:

### `InvalidCredentialsException.php`
```php
final class InvalidCredentialsException extends \DomainException
{
    public static function forEmail(string $email): self
    {
        return new self(\sprintf('Invalid credentials for email: %s', $email));
    }
}
```

### `UserDeactivatedException.php`
```php
final class UserDeactivatedException extends \DomainException
{
    public static function forUser(UserId $userId): self
    {
        return new self(\sprintf('User %s is deactivated', $userId->toString()));
    }
}
```

`AuthenticationService` выбрасывает:
- `InvalidCredentialsException` — если пользователь не найден или пароль неверен (общее сообщение для безопасности)
- `UserDeactivatedException` — если `isActive() === false`

Controller мапит:
- `InvalidCredentialsException` → 401 Unauthorized
- `UserDeactivatedException` → 403 Forbidden

## JWT конфигурация (ключевые параметры)

- `token ttl: 3600` (1 час)
- `algorithm: RS256`
- `private_key_path: '%kernel.project_dir%/config/jwt/private.pem'`
- `public_key_path: '%kernel.project_dir%/config/jwt/public.pem'`
- `pass_phrase: '%env(JWT_PASSPHRASE)%'` (в `.env` — случайная строка, в `.env.test` — `test_passphrase`)

Ключи генерируются командой:
```bash
mkdir -p config/jwt
openssl genrsa -out config/jwt/private.pem -aes256 -passout pass:"${JWT_PASSPHRASE}" 4096
openssl rsa -pubout -in config/jwt/private.pem -passin pass:"${JWT_PASSPHRASE}" -out config/jwt/public.pem
```
