# Task 4.5 — API-эндпоинты айтемов

## 1. Описание задачи

Application-слой айтемов готов (Task 4.4): `ItemService` (create/update/delete/getById/listByCollection/listByOwner/toDTO/toDTOList), `ItemSlotMapper`, DTO (`CreateItemDTO`, `UpdateItemDTO`, `ItemDTO`, `ItemSlotDTO`, `TagDTO`), `ItemRepositoryInterface`, `ItemNotFoundException`. Есть паттерн `CollectionController` (auth через `getUser()`, ownership-проверка, конверт ошибок) и `AbstractApiController` (`deserializeAndValidate` → `ValidationException` → 400).

**Чего не хватает:**

1. `ItemController` — REST-эндпоинты CRUD + списки отсутствуют.
2. Фильтров `?name=` / `?tags[]=` в `ItemRepositoryInterface` / `DoctrineItemRepository` / `ItemService` — нет.
3. Маппинга `\InvalidArgumentException` (невалидный слот из `ItemSlotMapper`) → 400 — нет (сейчас ушёл бы в 500).
4. Functional-тестов `ItemController`.
5. `security.yaml`: GET `/api/items` сейчас `PUBLIC_ACCESS` — противоречит решению D1 (только владелец+админ).

## 3. Решения (согласованы с пользователем)

- **D1.** Чтение айтемов — **только владелец и админ** (не public). Мутирующие — только владелец (админ — тоже допускается). Требует правки `security.yaml`.
- **D2.** Фильтр тегов — **AND** (айтем содержит все указанные теги), форма `?tags[]=a&tags[]=b`. Фильтр имени — подстрока `LIKE` (регистронезависимо через коллацию `utf8mb4_0900_ai_ci`).
- **D3.** `GET /api/items` — только свои айтемы. Расширение `?owner={uuid}` — Этап 5.
- **D4.** N+1 по тегам в списках — **отложено** в `fwd-6` (для MVP `limit<=50` терпимо; правильный фикс — двухзапросный batch).
- **D5.** Слоты **не сверяются** со схемой `CollectionField` (свободная валидация из 4.4).

### Эндпоинты

| # | Метод | Путь | Доступ | Успех |
|---|---|---|---|---|
| 1 | POST | `/api/collections/{collectionId}/items` | auth + владелец коллекции/админ | 201 `ItemDTO` |
| 2 | GET | `/api/collections/{collectionId}/items?limit&offset&name&tags[]` | auth + владелец коллекции/админ | 200 `ItemDTO[]` |
| 3 | GET | `/api/items?limit&offset&name&tags[]` | auth (свои) | 200 `ItemDTO[]` |
| 4 | GET | `/api/items/{id}` | auth + владелец айтема/админ | 200 `ItemDTO` |
| 5 | PATCH | `/api/items/{id}` | auth + владелец айтема/админ | 200 `ItemDTO` |
| 6 | DELETE | `/api/items/{id}` | auth + владелец айтема/админ | 204 |

**Коды:** 400 (валидация/невалидный слот/пустой PATCH), 401 (нет токена), 403 (чужой ресурс), 404 (`ItemNotFoundException`/`CollectionNotFoundException`).

**Конверт ошибок** (как в `CollectionController`):
- 400: `{"error":"Validation failed","details":[...]}`
- 400 (слот/PATCH): `{"error":"Bad Request","message":"..."}`
- 401: `{"error":"Unauthorized"}`
- 403: `{"error":"Forbidden","message":"..."}`
- 404: `{"error":"Not Found","message":"..."}`

**Фильтр тегов (AND)** — через `EXISTS`-подзапрос с `HAVING COUNT(DISTINCT t.name) = :nameCount`, чтобы не ломать пагинацию `setMaxResults` (без `GROUP BY` на основном запросе). Имена нормализуются через `TagName::fromString` (ci-совпадение по коллации).

## 4. Ограничения

- **Слои:** фильтры — в `ItemRepositoryInterface` (Domain) + `DoctrineItemRepository` (Infrastructure); `ItemService` проксирует; контроллер — Infrastructure.
- **UoW:** flush только в `ItemService` (`transactional()` на create/update, `flush()` на delete). Репозитории без flush.
- **Doctrine ORM 3:** read-методы списков уже JOIN FETCH `i.collection -> collection.owner` (final-сущности не проксируются); фильтры не должны ломать этот JOIN.
- **Пагинация:** `limit`/`offset` как в `/api/collections` (default 50/0). Ответ — плоский массив (консистентно с коллекциями).
- **security.yaml:** убрать `^/api/items` из `PUBLIC_ACCESS`; добавить правило `^/api/collections/[^/]+/items` → `IS_AUTHENTICATED_FULLY` **перед** `^/api/collections` GET (public, 3.4). Порядок правил важен — первое совпадение побеждает.
- **Миграции:** не требуются.

## 9. Заметки

- **N+1 тегов** — отложено (`fwd-6`). `ItemDTO::fromEntity` → `getTags()` на каждый item.
- **OWNER/ADMIN:** проверка через `$collection->getOwner()->getId()->equals(...)` или `$user->getRole()->isAdmin()`.
- **Фильтр AND + пагинация:** `EXISTS`-подзапрос с внутренним `GROUP BY ... HAVING` — GROUP BY внутри подзапроса, основной запрос (с JOIN FETCH и `setMaxResults`) не затрагивается.
- **Теги-фильтр:** имена нормализуются `TagName::fromString`; пустой нормализованный тег → исключается из фильтра (как в `TagService`).
- **Ошибки секьюрити:** при провале авторизации JWT-firewall вернёт 401 сам (после снятия PUBLIC_ACCESS).
