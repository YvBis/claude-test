## Открытый вопрос (не решается молча)

`symfony.lock` (строка 8) игнорируется — значит, дрейф версий рецептов
(`composer recipes:update`) не виден. Для 5.32 это безвредно (рецептный файл переписан
вручную и считается своим), но для остальных рецептов (`nelmio/api-doc`, jwt) — риск.
Оставлено как есть, вынесено здесь для явного решения.

## Guard-тест

`tests/Infrastructure/Ci/GitignoreConfigTest.php`, по образцу трёх существующих
конфиг-гардов (`CodeReviewConfigTest`, `DeprecationConfigTest`, `SymfonyLspConfigTest`).
Три теста: ни одно `!`-правило не касается логов (сегментное совпадение — `catalog`/`blog`
не шумят), `/var/` + `*.log` — единственное определение, дубликатов в собственной
(дорецептной) части файла нет. Утверждение про `/var/` означает: если будущий
`composer recipes:update` уберёт его из рецепта — тест упадет красным по дизайну, и это
контракт, а не баг.
**Без запуска git**: разбирает `.gitignore` в PHP и проверяет инварианты, которые чиним, —
присутствует `/var/`, ни одно `!`-правило не исключает `var/log` или `*.log`, дубликатов
паттернов нет. Парсинг вместо `git check-ignore` сознателен: не зависит от наличия git в
окружении и проверяет ровно то свойство, которое сломано («исключение не может перебить
более позднее правило»). Фактическую проверку `git check-ignore` делаем руками в проверках.

## Проверки
