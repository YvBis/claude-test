# 10.7 — Дрейф индексов `users`: мёртвые объявления вместо несуществующих индексов

## Что утверждал аудит и что оказалось

Аудит (R-05) утверждал: «индексы объявлены в маппинге, но не созданы — `users.idx_user_email`, `users.idx_user_is_active`, `likes.idx_like_created`».

Проверка по коду и схеме:

| Индекс | Утверждение | Факт |
|---|---|---|
| `likes.idx_like_created` | «нет в схеме» | **есть** — `Version20261011100000:24` (7.6b) |
| `comments.idx_comment_created` | не упоминался | **есть** — `Version20261011090000:24` (7.6a) |
| `users.idx_user_email` | «объявлен, не создан» | объявлен **мёртво** (см. ниже), в схеме отсутствует |
| `users.idx_user_is_active` | то же | то же |

**Механизм, который аудит не увидел.** Оба индекса объявлены внутри `#[ORM\Table(name: 'users', indexes: [...])]`. В Doctrine ORM 3 этот аргумент инертен: `Mapping\Table::__construct` (`vendor/doctrine/orm/src/Mapping/Table.php:25-33`) хранит значение, но триггерит deprecation («does not have any effect and will be removed in Doctrine ORM 4.0»), а `AttributeDriver` это поле не читает. То есть маппинг их **никогда не декларировал** — это мёртвый код, а не дрейф. Подтверждено замером: с этими объявлениями `getUpdateSchemaSql()` не содержит ни одного `CREATE INDEX`, а после переноса того же индекса в отдельный `#[ORM\Index(...)]` — содержит.

Полная сверка остальных 10 объявлений `ORM\Index` против трёх миграций — совпадают 1-в-1.

## Решение

1. Удалить `indexes:` из `#[ORM\Table]` в `User.php` (мёртвый + deprecated аргумент). Новой миграции **не нужно**: схема и маппинг сходятся и без них.
2. Не переносить индексы в `#[ORM\Index]`: `idx_user_email` дублирует префикс `UNIQUE(email)` (`Version20261003120000:49`) — второй BTREE даёт только стоимость записи; `idx_user_is_active` не читает ни один запрос (`DoctrineUserRepository` фильтрует по `id`/`email`/`role` и сортирует по `created_at`; флаг читается только в PHP — `UserProvider:37,53`).

## Гард

`tests/Infrastructure/Doctrine/SchemaIndexDriftTest` — пять инвариантов:

| Тест | Что держит |
|---|---|
| `testSchemaIsMigratedBeforeTheDiffIsTrusted` | БД мигрирована: иначе интроспекция не видит таблиц и дифф пуст, то есть гард проходил бы вхолостую |
| `testMappingDoesNotDeclareIndexesMissingFromMigrations` | в диффе нет `CREATE INDEX` |
| `testMappingDoesNotDropIndexesThatTheSchemaHas` | в диффе нет `DROP INDEX/KEY`, кроме трёх индексов ручных FK |
| `testOnlyHandWrittenForeignKeysAreDropped` | `DROP FOREIGN KEY` только для трёх `owner_id`-каскадов; сообщение подсказывает, куда добавить новую ручную FK |
| `testNoEntityPassesTheInertTableIndexesArgument` | ни одна сущность из метаданных не передаёт `indexes:`/`uniqueConstraints:` в `ORM\Table` — проверка через рефлексию атрибута, а не регуляркой |

Reflection вместо текстового скана выбран осознанно: он видит любую форму записи (алиасы, вложенные скобки, многострочность) и все сущности из метаданных, а не только `src/Domain`.

Allowlist — точные имена (`FK_D325D3EE7E3C61F9` и т.д., `IDX_…` для их индексов), не паттерны: `owner_id` — колонка без ORM-ассоциации, FK объявлены руками в миграции, и ORM о них не знает (это же зафиксировано в `ARCHITECTURE.md`).

«Дифф пуст» не пиним: platform-шум (charset/collation) меняется между версиями Doctrine. Проверяются только индексные и FK-statement'ы.

## Замеры красного

| Правка | Результат |
|---|---|
| добавить `#[ORM\Index(name: 'idx_user_is_active', ...)]` | `CREATE INDEX idx_user_is_active ON users (is_active)` → красный |
| вернуть `indexes:` в `#[ORM\Table]` | рефлексия по метаданным → красный |
| убрать `#[ORM\Index(name: 'idx_comment_created', ...)]` | `DROP INDEX idx_comment_created ON comments` → красный |

Все три откатаны, дерево чистое.

**Замер по allowlist:** три `DROP INDEX` для индексов ручных FK действительно появляются в диффе (измерено на мигрированной БД), поэтому они в allowlist по факту, а не «на всякий случай». Удаление объявления обычного индекса (проверено на `idx_comment_created`) даёт `DROP INDEX` и краснит гард; для индекса, который MySQL держит под FK, Doctrine `DROP INDEX` не предлагает (проверено на `idx_like_item`) — это ограничение записано здесь, а не спрятано.
