# Задача 8.5 — Проверка полноты документации OpenAPI

**Статус:** done
**Задача Roadmap:** 8.5 — Проверка полноты документации OpenAPI

## Контекст

Спека (`public/api/openapi.json`) уже под двумя охранами: `OpenApiSpecTest` морозит контракт,
который надо ревьюить осознанно (операции, коды ответов, схемы, `Error`-ref на всех 4xx/5xx),
а `scripts/check-openapi-fresh.sh` (первый шаг `ci:static:quality`) байт-в-байт сверяет
закоммиченный файл со свежим дампом. Обе охраны смотрят **на спеку**, и ни одна не спрашивает
роутер, что он реально отдаёт.

Отсюда два класса дыр, которые ни один из существующих гейтов поймать не может:

1. **Роут есть, аннотации нет.** Дамп просто не содержит операцию, спека перегенерируется —
   и обе стороны снова «свежие». Freshness этого не видит по построению.
2. **В спеке операция, которой нет в роутере.** Обратный случай, тоже невидимый для freshness.

Плюс два свойства, которые нигде не зафиксированы как контракт: **кто может звать операцию**
(токен обязателен / опционален / не нужен) и **какие POST/PATCH легально без тела**.

## Замеры (по факту, до кода)

| Метрика | Значение |
|---|---|
| Роуты в test-ядре | 35 (`GET /health` + 34 `/api*`); фреймворковых (`_preview_error` и пр.) нет |
| Операции в спеке | 35 |
| Расхождение роутер ↔ спека | пусто в **обе** стороны |
| `deprecated` в спеке | ровно одна: `DELETE /api/comments/{id}` (flat, fwd-18) |
| Операции без `security` | ноль |
| Токен не нужен (`security: []`) | 3: `/health`, `POST /api/login`, `POST /api/register` |
| Токен опционален (`[{Bearer}, []]`) | 8 — ровно гостевая поверхность fwd-7 |
| POST/PATCH без тела | 2: `POST /api/logout`, `POST /api/items/{itemId}/likes` |
| Операции без `operationId`/`summary`/`description`/`tags` | ноль |

Вывод замера: **API уже полон**, гэпов нет. Ценность 8.5 — не починка, а **guard**, который
держит это состояние: ни freshness, ни спек-тест двустороннее равенство с роутером не проверяют.

## Решения (и почему)

**D1 — тест `OpenApiCompletenessTest`, `KernelTestCase`, роутер через `RouterInterface`.**
Образец — `AdminGuardTest`: `bootKernel()` + `getContainer()->get(RouterInterface::class)`,
без HTTP-проб и без БД (нужна только маршрутизация). Роуты, чьё имя начинается с `_`,
пропускаются структурно: это плумбинг фреймворка (`_preview_error` в debug-ядре), а не
поверхность API; исключение по имени, а не по списку, потому что список пришлось бы обновлять
на каждом изменении фреймворка.

**D2 — равенство множеств роутер ↔ спека, точное, включая имена плейсхолдеров.**
Нормализации `{itemId}` → `{id}` нет намеренно: OA-путь написан руками рядом с `#[Route]`,
freshness сравнивает дамп сам с собой, поэтому опечатка в аннотации доехала бы до клиента
молча — а сглаживание спрятало бы ровно её. Два ассерта с разными сообщениями: «роут есть,
операции нет» и «операция есть, роута нет».

**D3 — deprecated проверяется абсолютно, а не паритетом с аннотацией.**
Паритет «код ↔ спека» уже гарантирован freshness (обе стороны перегенерируются вместе) и
потому не имеет сигнала. Абсолютный ассерт — `paths['/api/comments/{id}'].delete.deprecated
=== true`, nested-DELETE — не deprecated, и ровно одна deprecated-операция в спеке: новая
deprecation это изменение контракта и должна быть здесь названа.

**D4 — security как контракт из трёх частей.** У каждой операции `security` обязан
присутствовать; `[]` — ровно `PUBLIC_OPERATIONS` (3, с причиной), `[{Bearer}, []]` — ровно
`OPTIONAL_AUTH_OPERATIONS` (8, гостевая поверхность fwd-7, с причиной), всё остальное — строго
`[{Bearer: []}]`. Вывод из `401` не годится: `POST /api/login` публичный, но документирует 401
(неверные учётные данные) — проверка «есть 401 ⇒ нужен токен» была бы ложной.

**D5 — тела запросов: схема обязательна, кроме явно перечисленных.** POST/PATCH обязаны
объявлять `requestBody` с JSON-схемой, у которой есть `properties` (или `$ref`, резолвящийся в
объявленную схему); исключения — `BODY_LESS` (2, с причиной). Новый POST, потерявший тело,
краснит тест.

**D6 — проза не проверяется, только наличие.** `operationId`/`summary`/`description`/`tags`
непусты — это факт на сегодня и полезный контракт (сгенерированному клиенту нужно имя операции),
но «хорошо ли написано» тест не судит: иначе 8.5 превратилась бы в рерайт спеки.

**D7 — `openapi:validate` оставлен как есть.** Сейчас это no-op (`|| true`), и трогать его
незачем: аннотации валидируются на этапе дампа (невалидная аннотация роняет
`openapi:generate`, а значит и freshness-гейт), а структурную валидность JSON гарантирует
`JSON_THROW_ON_ERROR` в самих тестах. Отдельный OpenAPI-валидатор — новая зависимость без
покрытой потребности; записано как «не делаем», чтобы это не выглядело забытым.

**D8 — типы и форматы параметров не проверяются (осознанно).** Ревью синьора указало, что
`OpenApiSpecTest` морозит у параметров только `name`/`in`/`required`, а `schema.type`/`format`
не заморожен нигде, и `@OA\Parameter` с неверным типом доедет до клиента молча. Проверять это
из роутера нельзя — тип параметра живёт только в аннотации, сверить его не с чем; а заморозить
абсолютные значения значило бы вписать в тест копию спеки и обновлять её на каждое изменение.
Оставлено вне 8.5 как «не делаем» с причиной, чтобы это не выглядело забытым. Отдельный
кандидат — типы ответов/полей в `components.schemas`, если появится реальная потребность.

## Красные пробы (тест обязан уметь падать)

Гард, который не может упасть, — украшение, поэтому сигнал проверен на живой спеке:

1. Убрал `"deprecated":true` из спеки → `The flat comment DELETE must carry deprecated: true…`,
   `FAILURES! Tests: 6, Assertions: 243, Failures: 1` (счёт ниже зелёного, потому что ассерт
   падает раньше остальных). Спека восстановлена (`git checkout`).
2. Переименовал путь `/api/tags` → `/api/tags-ghost` → `These routes exist but are not in the
   spec. Add the OA annotation, or add the route to NOT_DOCUMENTED with a reason.`,
   `FAILURES! Tests: 1, Assertions: 4, Failures: 1`. Спека восстановлена.

Плюс негативный зонд в самом тесте: общий хелпер `missingFrom()` обязан назвать отсутствующую
запись по имени, а дубликаты и идентичные множества — не считать дрейфом.
