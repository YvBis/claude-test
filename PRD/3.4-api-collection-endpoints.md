# PRD — Task 3.4: API-эндпоинты коллекции (список чужих коллекций)

## Контекст

Аудит показал: задача 3.4 почти полностью закрыта коммитом `6ec3dd7` (#25), уже замерджена.
Функционируют: POST /api/collections, GET /api/collections/{id}, GET /api/collections (свои,
limit/offset), PATCH, DELETE + OpenAPI-док + 9 функц. тестов.

**Дельта задачи 3.4:** «список чужих коллекций» (требование `artifacts/prd-taskflow-ru.md`,
строка 18, user story «получить список чужих коллекций»).

## Цель

Пользователь (авторизованный) может получить список коллекций другого авторизованного
пользователя по его id.

## Решение (архитектурное)

Расширить `GET /api/collections` опциональным query-параметром `owner={uuid}`:

- `owner` отсутствует → список СВОИХ коллекций (текущее поведение, обратная совместимость)
- `owner` задан (валидный UUID) → список коллекций этого пользователя
- `owner` — невалидный UUID → 400 `{"error": "Invalid owner id"}`
- `owner` задан, но у пользователя нет коллекций → 200 `[]`

Бизнес-правила:
- Доступ к чужим коллекциям в MVP публичный (приватности нет), RBAC-проверок владельца нет.
- Пагинация пределом существующим: `limit` (default 50), `offset` (default 0).
- Оба параметра списка: аутентифицированный доступ (401 без Bearer), как весь контроллер.

Слои:
- **Domain**: `CollectionRepositoryInterface::findByOwnerId(UserId $ownerId, int $limit, int $offset): array`
  — реализация в Doctrine рее через `IDENTITY(c.owner) = :ownerId` (без загрузки сущности User).
- **Application**: `CollectionService::listByOwnerId(UserId $ownerId, int $limit, int $offset): array`
  — декоратор над repo, DTO-трансформация (toDTOList).
- **Infrastructure**: контроллер — разбор `owner`, валидация UUID через `UserId::fromString`
  (бросает `\InvalidArgumentException`).

## Критерии приёмки

1. `GET /api/collections?owner={B-id}` авторизованным A возвращает 200 + список коллекций B.
2. Тот же запрос A возвращает 200, НЕ содержащий коллекций A.
3. `owner=<мусор>` → 400.
4. `owner=<нет коллекций>` → 200 `[]`.
5. Существующие тесты list (свои) не сломаны.
6. `composer ci:all` зелёный (после `rm -rf var/cache/test`).
7. Ревью тремя параллельными субагентами до PR (по процессу 3.4).
