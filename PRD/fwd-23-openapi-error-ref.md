# PRD: fwd-23 — `$ref` на общую схему ошибок в OpenAPI

Задача из Review Backlog (`Roadmap.md`, строка `fwd-23`). Заведена 2026-09-22
(architect-review 5.9). Реализация — 2026-09-27, волна 1 зафиксированной очереди
(после fwd-27/fwd-28, перед fwd-18 — закрывает мини-этап 5A).

## Зачем

Аннотации ошибок дублировали inline-определение конверта `{error, message, details}`
(найдено: 20 мест в 5 контроллерах), а 57 аннотаций ошибок вообще не описывали тело
ответа — спека молчала о том, что лежит в 401/403/404. Мини-этап 5A заморозил конверт
как контракт; спека обязана его отражать одной схемой, а не двадцатью копиями.

## Замер (2026-09-27, до реализации)

Формулировка в Roadmap («~30 inline-блоков 422 в 8 контроллерах») неверна в обе стороны:

| Факт | Значение |
|---|---|
| Всего error-аннотаций (400/401/403/404/409/422) | 77 |
| Из них 422 | 8 |
| Inline-схема (`content:` с объектом) | **20**: Collection 12, Login 3, Registration 2, Comment 2, Logout 1 |
| Description-only (без схемы) | **57** |
| Контроллеры вообще без error-схем | Item, Tag |

Метод: `grep -c 'response: 4xx'` по контроллерам + многострочный regex
`response:\s*4\d\d[\s\S]{0,500}?content:` с ручной сверкой. Item/Tag ошибок со
схемами не имеют — их аннотации только пополняются `ref`, нового дублирования нет.

## Объём (решение пользователя 2026-09-27: все 77)

- Одна схема `Error` в `config/packages/dev/api_doc.yaml` (`components.schemas`,
  YAML-объект): `error` (string, required), `message` (string), `details` (`string[]`).
  Отдельный `ErrorDetails` не нужен — `details` живёт внутри `Error` (подтверждено
  senior-review fwd-27). Место — конфиг, а не `#[OA\Schema]`-атрибуты: nelmio
  перезаписывает `components` из конфига, атрибутные компоненты теряются
  (зафиксировано в `ARCHITECTURE.md`).
- 20 inline-блоков → `content: new OA\JsonContent(ref: '#/components/schemas/Error')`
  (та же идиома, что уже применена к успешным ответам, `ItemController:220`).
- 57 description-only аннотаций → тот же `ref`. Per-endpoint `description` остаются —
  смысл каждого ответа живёт в них; теряются только тексты примеров в `details`.
- `public/api/openapi.json` регенерируется (`composer openapi:generate`) и коммитится
  (файл трекается; CI-шага для него нет — дрейф виден только глазами, см. ниже).
- Строка `fwd-23` в Roadmap правится (старая формулировка неверна).
- Дрейф закоммиченной спеки относительно свежего дампа — класс задачи `fwd-11`
  (политика авто-генерируемых трекаемых артефактов), вписан туда подпунктом (c).

## Вне объёма

- 5xx-аннотаций в спеке нет вообще (ни одного `response: 5xx`), хотя конверт 500
  заморожен в 5A. Документировать 500 на каждой операции — ещё 30+ аннотаций с низкой
  информативностью («упасть может всё»); кандидат в бэклог, не сюда.
- Success-схемы (200/201/204, в т.ч. inline-объекты коллекций) не трогаем.
- Отдельный `ErrorDetails` не заводим.
