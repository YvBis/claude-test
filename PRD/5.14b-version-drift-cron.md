# PRD — 5.14b: регулярная проверка версии symfony-lsp (version-drift cron)

**Статус:** active. Закрывает третью часть строки 5.14 («завести регулярную
проверку версии `symfony-lsp`: 0.x-релизы частые, Dependabot скачиваемый
бинарник не видит»). PR-A (пин + блокирующий флип + `symfony-lsp-gate.php`)
смержен как `a65209c` (PR #109).

## Гипотезы (до реализации)

- **H1 (два якоря):** версия запинена в двух местах —
  `scripts/symfony-lsp-check.sh:40` (дефолт `VERSION="${SYMFONY_LSP_VERSION:-…}"`)
  и `.github/workflows/ci.yml:82` (`SYMFONY_LSP_VERSION: '…'`), причём
  эффективная версия CI — из ci.yml (env переопределяет дефолт скрипта).
  Гард-тест проверяет лишь наличие (`SymfonyLspConfigTest`, presence, не
  равенство). Крон читает оба источника и предупреждает об их расхождении как
  о самостоятельном дефекте. Читать регекс guard-теста — неверно: истина живёт
  в продюсерах (урок 5.31 применён правильно), а тест ослеп бы ровно тогда,
  когда скрипт и тест разойдутся.
- **H2 (эндпоинт):** `GET /repos/symfony/language-tools/releases/latest`
  отдаёт объект (не массив) с `tag_name: "v0.23.0"` (`v`-префикс снимать),
  `draft`/`prerelease` исключены контрактом самого GitHub. Проверено синьором
  живьём. Альтернатива `/releases?per_page=N` + `select()` — самопроверяющаяся,
  но тяжелее; выбран `/latest`.
- **H3 (advisory):** апстримный каденс релизов не контракт — дрейф не должен
  краснеть и тем более блокировать мержи (ruleset править не надо). Скрипт
  всегда выходит 0; при недоступном API — отдельное сообщение «версия не
  проверена» ≠ «версия устарела» (ветка как в 5.19A: «API недоступен → вердикт
  не проверен»). `set -euo pipefail` + гарантированный exit 0 требует
  `EXIT`-trap по образцу `verify-review-verdict.sh:79-88` плюс `|| true` на
  каждой падающей подстановке; без trap'а первый упавший `curl`/`jq`/`grep`
  сломает advisory-контракт. bash 3.2, без assoc-массивов.
- **H4 (каденс апстрима):** v0.22.0 вышел 2026-09-25, v0.23.0 — 2026-09-26
  (замер синьора): ежедневный каденс 0.x. Еженедельный крон попадает в окно;
  месячный оставил бы пин просроченным на месяц. Шума ноль — advisory.
- **H5 (бонус API):** `asset.digest` релиза несёт `sha256:…`, совпадающий с
  нашим пином (проверено синьором). Предупреждение печатает готовый рецепт
  бампа с хешем из API — меньше ручных ошибок, чем копирование со страницы
  релиза.
- **H6 (живость расписания):** гард-тест, утверждающий наличие `schedule:`,
  проверяет wiring, а не живость — расписание может не сработать (простой
  репо 60+ дней глушит cron'ы, сами прогоны могут лагать), и тест этого не
  увидит. Живость доказывается историей прогонов, а не тестом. Записано явно,
  чтобы тест не приняли за доказательство.

## Решения пользователя (с ценой)

- **Warning-only, без issue.** Issue-режим требует `issues: write`, жизненный
  цикл маркера и правило закрытия при бампе — машинерия ради боли, которая
  ещё не наблюдалась. Паттерн 5.19A не переносится как есть: его маркер
  ключуется по head SHA (`verify-review-verdict.sh:115`), а у планового
  прогона нет ни PR, ни head SHA. Возврат к issue — после первого реального
  предупреждения в истории прогонов.
- **Еженедельно** (off-peak минута). При ежедневном каденсе апстрима месяц —
  слишком редко, неделя — в самый раз.

## Границы

- Крон никогда не падает и не входит в гейт: `needs:` у `ci-summary` не
  трогаем, ruleset не трогаем, required-чеки не трогаем. Новый workflow-файл,
  а не job в `ci.yml` (у него триггеры только push/PR + `concurrency` —
  расписание там чужеродно).
- В коммит не идёт никакой устаревший пин: двустороннее доказательство — на
  `/tmp`-копии скрипта.
- `gh api` вместо `curl` (прецедент `verify-review-verdict.sh:139`):
  авторизация токеном, минус лимит 60/ч для анонимных запросов. `jq` доступен
  на `ubuntu-latest` (на него уже опирается `ci.yml:295`).
- Ручной backstop простоя: если workflow не срабатывал ≥14 дней (GitHub глушит
  расписания на неактивных репо от 60 дней, сами прогоны могут лагать) —
  запустить вручную `gh workflow run dependency-drift.yml`.
- `actions/checkout@v4` — как в `ci.yml` (единый пин; v5 не тянем отдельным
  PR ради одного workflow).
