# PRD 5.12 — Убрать deprecated `encoder.crypto_engine`

> **Дополнено задачей 5.13 (2026-09-22).** Runtime-прогон, которым проверялась эта находка, промоушен в CI: job `symfony-diagnostics` теперь делает его с явным `--environment=test`. См. `PRD/5.13-symfony-lsp-runtime.md`.

Этап 5 (Социальное), review-задача. Найдено автоматически: `symfony-lsp check` (runtime-режим) выдал `config.deprecated_key`.

## Находка

`config/packages/lexik_jwt_authentication.yaml`:

```yaml
encoder:
    crypto_engine: 'openssl'          # строка 8 — deprecated
    signature_algorithm: 'RS256'
```

## Почему удаление безопасно

Схема самого бандла (из сгенерированного `config/reference.php`, который является дампом схемы конфигов):

> `crypto_engine?: "openssl"|"phpseclib"|Param` — **Deprecated: The "lexik_jwt_authentication.encoder.crypto_engine.crypto_engine" configuration key is deprecated since version 2.5, built-in encoders support OpenSSL only** // Default: "openssl"

- ключ устарел с версии 2.5, установлен `lexik/jwt-authentication-bundle` **v2.21.0**;
- встроенные энкодеры поддерживают **только OpenSSL**, и дефолт — `openssl`;
- значит удаление строки **поведение не меняет**: тот же движок берётся по умолчанию.

Дополнительно проверено: конфиг lexik в проекте **единственный** (нет переопределений в `config/packages/dev|prod|test`), других вхождений `crypto_engine` в `config/`, `src/`, `tests/` нет, `JWT_PASSPHRASE` (в `.env`/`.env.test`) не затрагивается.

## Что НЕ входит

- **`config/reference.php`** — не трогаем. Это **дамп схемы** конфигов бандлов (`PhpConfigReferenceDumpPass`, регистрируется `FrameworkBundle` только при `kernel.debug`), а не наши значения: строка про `crypto_engine` присутствует там как часть схемы **Lexik** и после удаления нашей YAML-строки остаётся. Плюс содержимое зависит от окружения (`.kernel.bundles_definition` — DAMA только в test, Nelmio в dev+test), поэтому перегенерация даёт либо пустой дифф, либо посторонний шум. Политика для файла — задача **fwd-11**, она расширяется фактами из этого разбора.
- **Runtime-режим checker'а в CI** — отдельная задача 5.13; здесь только локальное доказательство закрытия находки.
- Изменения остальных ключей JWT (`token_ttl`, `clock_skew`, алгоритм) — не в скоупе.

## Риски

- **Регрессия-mute**: source-only режим checker'а в CI **не видит** deprecated-ключи конфигов (они всплывают только при runtime-анализе) — поэтому регрессионная сетка для этой находки именно guard-тест, а включение runtime в CI — задача 5.13.
- **Статический guard-тест** проверяет файл, а не эффективную конфигурацию контейнера: эффективное значение совпадает до и после (дефолт `openssl`), поэтому проверять контейнер бессмысленно — смысл теста в фиксации «ключ не вернулся в YAML».
- Локальные грабли: LF-нормализация перед phpcs (историческая заметка: снято в 5.21 — `.gitattributes` нормализует checkout); чистка `var/cache/test` после правок; дрейф `config/reference.php` от прогонов — ревертить.
