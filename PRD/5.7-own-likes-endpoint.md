# PRD 5.7 — API-эндпоинт «мои лайки» (`GET /api/likes`)

Этап 5 (Социальное), review-задача. Симметрия с `GET /api/comments` (5.5 отдала только «мои комментарии» — PRD artifacts, требование 20: «менять свои лайки и комментарии у айтемов»).

## Цель

Аутентифицированный пользователь получает пагинированный список **своих** лайков (старейшие первыми), в формате `LikeDTO[]` — зеркально `GET /api/comments`.

## Эталон

`CommentController::listOwn` (`src/Infrastructure/Api/Controller/CommentController.php:158-204`):
`GET /api/comments` → 401 без токена → `parsePagination` (400 при невалидной) → `listByOwner(OwnerId::fromBytes($user->getId()->toBytes()), $limit, $offset)` → `toArrayPayload(toDTOList(...))` → 200.

## Что НЕ входит

- **`countByOwnerId` для Like** — эндпоинт не отдаёт счётчики; не плодим неиспользуемый код (у `Comment` он есть, но там тоже без консьюмера — наблюдение review, не дефект).
- **`security.yaml`** — `^/api` → `IS_AUTHENTICATED_FULLY` уже покрывает `GET /api/likes`; изменений нет.
- **Гостевой доступ** — остаток fwd-7; эндпоинт auth-only, как «мои комментарии».
- **Рефактор конвертов ошибок (5.9)** — 5.7 пишется в текущем ручном стиле; 5.9 затем отрефакторит новые строки.

## D-решения

- **Порядок `createdAt ASC, id ASC`** — симметрия с комментариями (требование 5.7), детерминированный tiebreaker при равных микросекундах.
- **Без `countByOwnerId`** — YAGNI: эндпоинт возвращает только список; лишние методы без консьюмера — scope creep.
- **Ручной стиль ошибок** — осознанно до 5.9 (иначе конфликт/дублирование работы).
- **N+1 отсутствует** — `withAll` тянет owner + item + collection + collectionOwner одним запросом (как у Comment); fwd-8 про счётчики в списках айтемов — не этот случай.
- **`toggle`/`isLikedBy` не трогаем** — вне скоупа.
- **Covering-индекс `idx_like_owner`** (находка architect-ревью, принята): `findByOwnerId` фильтрует по `owner_id` и сортирует по `(created_at, id)` — без композитного индекса каждая страница делает filesort по всему сету лайков владельца. Зеркало `idx_comment_owner` (Task 5.2). `uniq_like_owner_item` фильтр покрывает, но сортировку — нет.

## Риски

- **`openapi.json` — generated + tracked**: после добавления `#[OA\Get]` обязательна регенерация, иначе док и код разойдутся. Включено в S6.
- **Покрытие не вырастет заметно** — новый код маленький; guard: покрытие слоя не падает ниже текущего.
