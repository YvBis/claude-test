## Замеры до кода (авторизация)

Три механизма (ARCHITECTURE, «Авторизация»): Voter через ADM (`SocialContentVoter`,
strategy `unanimous`, fwd-15) / owner-or-admin вне ADM (`OwnerAccess`, fwd-33 закрыл последнее

## Решения (и почему)

**D1 — два guard-теста, оба от роутера/рефлексии, без HTTP-sweep.**
`RouteAccessGuardTest`: гонится от `RouteCollection`, каждая мутирующая дорога — явная
классификация `public` / `admin` / `owner-or-admin` / `voter`; неклассифицированная новая
дорога краснит. Механические ячейки — только guest-401 (по access map) и admin-атрибут;
stranger→403 доказывается функциональными spot-чеками, в guard'е это написано явно, без
претензии на «матрицу» (синьор: owner-or-admin — императивный вызов в теле контроллера,
рефлексией не выводится). База — `GuestReadTest`, а не параллельный статичный список.
`ValidationUpperBoundTest`: каждый `Assert\Length` в `src/Application` несёт кастомный
`maxMessage` (инвариант D11) + негативный зонд. Формулировка «у каждого строкового поля есть
Length» ложна (`CommentRequestDTO` пуст, граница 1..3000 живёт в `CommentContent`) и не
используется.

**D2 — причёсывание ограничений, вариант A (полный единый источник).**
Числа и списки — именованные константы в домене; проверки остаются в обоих слоях
(DTO-превалидация с человеческими сообщениями → 422; домен-инфорсмент с `sprintf` + та же
константа), потому что валидатор вызывается только на DTO и доменные `Assert`-атрибуты
инертны по дизайну. Сообщения — только в DTO. Choice — через
`callback: [X::class, 'values']` (ноль новых копий, `values()` уже выводится из enum).
OA-слой (`OA\Property(minLength/maxLength)`, `enum` в контроллерах + `api_doc.yaml`) — тоже на
константы: спека в проекте собирается из ручных аннотаций, DTO-атрибуты Nelmio не видит,
поэтому без OA-слоя «единый источник» недостижим. Проверка нейтральности — регенерация спеки
до/после с пустым diff (теперь это настоящее доказательство).

**D3 — что осознанно не выравнивается.** `CollectionName` меряет байтами (`strlen`),
DTO — UTF-8: предсуществует, молча менять юниты нельзя (смена поведения), только
документируем. `changeName` не проверяет min-2: MIN-конста на сущности DTO-facing, фиксируем
как есть. `openapi:validate` остаётся no-op; проза спеки и типы параметров не морозятся.
`UserName` VO не вводим (43 call-сайта `register()`/`new User()` + фабрика — не «только
видимость»); имя пользователя — public-консты на `User`.

**D4 — находки без кода.** Rate limiting — принятый риск + `[review]`-строка «лимитер на
login/register». Заголовки безопасности/`/api/doc*` публично — находки в отчёт без фикса
(нет TLS → HSTS N/A; деплой-вопрос). Продуктовые лимиты входов (кардинальность `tags[]`/
`slots[]`, тексты) — заглушки без требований: инвентарь + `[review]`-строка «задать
продуктовые лимиты, когда появятся требования». Все `[review]`-строки пишутся **до** закрытия
8.6. 409 на register — принятое UX-решение, не находка.

## Замеры по ходу (часть 2, вариант A)

**Третья копия, пропущенная в плане (находка синьора, подтверждена).** Спека собирается из ручных
`OA\Property`/`enum` в контроллерах (22 сайта) + ручных схем `config/packages/dev/api_doc.yaml`
(4 сайта: 3 enum + `Comment.content` 3000) — Nelmio не видит DTO-`Assert`, поэтому дамп был бы
байт-идентичен при любом исходе DTO-рефактора. Следовательно: единым источником DTO↔домен
недостижим без OA-слоя, а «перегенерируй спеку» как доказательство нейтральности — пустое
без проводки констант в `OA\*`. Принято: вариант A (пользователь).

**Инвентарь третьей копии (все значения до правок):** user name 2/100 (register + admin-create),
email 255 (login/register/admin-create), password 8/255 (login/register/admin-create),
collection name 3/100 (create/update), theme enum (create), description/image 500 (create/update),
comment content 3000 (create/update), item name 100 (create/update), slot type enum + slot
minimum 1/maximum 3 (create), role enum (admin-create/admin-update + ответ register).

**Choice — через `callback`, не const-массивы (синьор).** `Theme::values()`, `Role::values()`,
`FieldType::values()` уже выводятся из enum — `#[Assert\Choice(callback: [X::class, 'values'])]`
даёт ноль новых копий при том же порядке и сообщениях. OA-`enum` остаются литералами:
аргументы атрибутов не могут вызывать функции, а заводить `public const array` ради них —
третье представление одного списка; их держит guard-таблица по спеке.

**Юниты не выравниваем (синьор).** `CollectionName` меряет байтами (`strlen`), DTO — UTF-8;
предсуществует, молча менять — смена поведения. Только документировано в PRD.

**`changeName` без min-2, `description` без доменного дома, plain-max без домена** — зафиксировано
комментариями у констант (`User`, `Collection`, `PasswordHash`): DTO-facing/API-лимиты, не
доменные инварианты.

**Доказательство нейтральности — настоящее.** `composer openapi:generate` после всех правок:
структурный diff старой и новой спеки — ровно **одно** семантическое отличие: добавленное
`maxLength: 255` на email в `POST /api/admin/users` (в спеке его не было, хотя DTO валидирует
всегда — осознанный documentation fix, единственное намеренное изменение). Всё остальное
байт-в-байт то же: числа, порядки enum, сообщения.

**Мутационный гейт на PR (поймано CI, закрыто тестом).** Diff-scoped прогон на этом PR дал
Covered MSI 87% против порога 88%: один выживший `GreaterThan`-мутант на строке, которую
задел рефактор (`User::changeName`, `>` → `self::MAX_NAME_LENGTH` + `sprintf`). Граница
«ровно 100 принято» не была покрыта (тесты проверяли пустое и 101). Исправление честное,
а не подгонка гейта: добавлен `testChangeNameAcceptsExactlyMaxLengthName` (ровно
`MAX_NAME_LENGTH` принято), мутант проверен локально (симуляция `>=` краснит новый тест,
восстановлено). Гейт после этого — зелёный.
