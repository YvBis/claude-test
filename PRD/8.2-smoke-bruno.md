# PRD 8.2 — Smoke-папка Bruno (локальная, без CI)

**Статус:** done
**Задача Roadmap:** 8.2 — Smoke tests (docker compose up и проверка URL)
**Оценка:** ≤ 2 человеко-часов, ~150 строк (`.bru` + доки)

## 1. Контекст и решения

8.1 (E2E-коллекция `tests/E2E/`, 12 запросов против собранного стека) и 8.7 (гонка готовности
БД) смержены. Строка 8.2 требует smoke «с переиспользованием job-инфры 8.1, а не вторым
`docker compose up`».

Принятые решения (пользователь + senior-review плана):

1. **Единообразие: только Bruno.** Второй харнесс (shell + curl) отвергнут: локальным
   разработчикам Node уже нужен для `bru run --env local`, а второй язык тестов — цена без
   выгоды. Зафиксировано здесь и пометкой в `ADR/0002-e2e-client.md`.
2. **Без CI-проводки.** Отдельный blocking-job невозможен без второго `up` (раннеры изолированы —
   общий стек между job'ами не делится), а шаг внутри job `e2e` дал бы только раннее падение:
   `/health` уже пробуется, bru покрывает те же пути секундами позже. Инкрементальная ценность
   CI-шага не окупает даже его. Smoke — локальный инструмент разработчика.
3. **Честно:** покрытие smoke — подмножество e2e; ценность — скорость локальной проверки
   («поднялось и отвечает за ~10 с»), а не новое покрытие.

Следствие для артефактов: `PRD/1.5-ci-pipeline.md:95` («Smoke — отдельный workflow») и
`README.md:262` (та же строка) отменяются этим PRD как устаревшие.

## 2. Состав

**`tests/E2E/smoke/`** — папка коллекции Bruno, ~5 запросов, только статусы + минимум полей:

1. `01-register.bru` — `POST /api/register`, случайный `smoke_<ts>@example.com` → 201,
   `bru.setVar` только для `email` (цепочка: email → login → token; `userId` никому не нужен).
2. `02-login.bru` — `POST /api/login` той же парой → 200, `bru.setVar("token", ...)`.
3. `03-my-items.bru` — `GET /api/items` с токеном → 200 (пустой список допустим).
4. `04-search.bru` — гостевой `GET /api/search/items?q=smoke` → 200 (движок жив).
5. `05-admin-forbidden.bru` — `GET /api/admin/users` с юзер-токеном → 403.

Запуск: `cd tests/E2E && bru run smoke --env local` (папки поддерживаются CLI: `bru run` —
«one or more requests/folders», флаг `-r`). Env `local`/`ci` уже есть (дележка с e2e);
`ci`-env smoke не используется в CI — он для единообразия формата.

Сайд-эффект: одна строка юзера в dev-БД за прогон (self-delete эндпоинта нет, админское удаление
требует админских прав — стадия 7). Мусор приемлем на dev-стеке, префикс `smoke_` делает его
видимым; в CI-стеке БД сносится `down -v`.

**Граница коллекции (поймано ревью).** Голый `bru run` в `@usebruno/cli@4.2.1` **рекурсивен**:
без пути он выполняет и `smoke/` — измерено локально (17 запросов вместо 12). Это ломало бы
два контракта сразу: CI-job гонял бы smoke вопреки решению (а гостевой поиск smoke на свежем,
непровижинированном движке job'а дал бы 500 — красный CI), и локальный рецепт e2e молча менял бы
смысл. Фикс: все 5 smoke-запросов несут meta-тег `smoke` (канонический синтаксис `.bru`,
проверен по `jsonToBru.js` сериализатора), а прогоны journeys — с `--exclude-tags=smoke` (и в
`ci.yml`, и в локальном рецепте README). Папочный `bru run smoke` тег не трогает. Доказательство:
локально `--exclude-tags=smoke` → 12/12, 18/18; `bru run smoke` → 5/5, 7/7.

Ассерты — строго статус-коды + наличие ключевых полей (id/token), **без парсинга тел**:
иначе переоткрывается ADR-0002 (там shell отвергнут за отсутствие декларативных ассертов).

## 4. Что НЕ входит

- Shell-скрипт, CI-шаг, CI-job, отдельный workflow — отвергнуты выше.
- Расширение smoke бизнес-ассертами (поля, пагинация) — это e2e, не smoke.
- Факторинг wait-циклов в composite-action — кандидат 8.2 из строки, но третий потребитель
  (meilisearch-wait) не появился; YAGNI, не сейчас (позиция architect-review 8.7).

## 5. Доказательство

Зелёный локальный прогон `bru run smoke --env local` (5/5 запросов) — основное доказательство.
`ci:all` PHP не трогает (прогон для регрессии) + `bru` валидирует JSON коллекции при запуске.
CI на PR — формальность (job `e2e` должен остаться зелёным; smoke-папка его не затрагивает).
