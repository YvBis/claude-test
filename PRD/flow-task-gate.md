# PRD flow-task-gate — закрыть лазейку «починки среды» и гейт ветки без задачи

**Статус:** done
**Основание:** прямая явная инструкция пользователя (внеплановая docs-правка правил; строки в
`Roadmap.md` не требует — см. п. 2 CLAUDE.md «Запрещено», исключение для инструкции пользователя).

## 1. Инцидент, который закрывается

После мерджа задачи 8.1 первый прогон CI на `main` (коммит `10fb0cd`) упал на шаге миграций
(`SQLSTATE[HY000] [2002] Connection refused`). Агент воспринял это как «сломанную среду» и завёл
ветку `fix/8.1-e2e-db-readiness` + PR #160 + полный цикл ревью/CI **без строки в Roadmap** — то
есть выполнил работу вне Workplan. Ветка и PR были отменены по требованию пользователя.

Разбор показал: запрет «создавать новые задачи вне Workplan» (`CLAUDE.md`, п. 2) уже существовал и
не был нарушен буквально — он был **обойдён через лазейку** в п. 3: «Починка среды не считается
задачей из Roadmap». Определения «среды» в правилах не было, а красный `main`, вызванный
содержимым репозитория, нигде не назван дефектом (а не сломанной средой).

## 2. Решение (вариант М1 — правки текста)

В `CLAUDE.md` внесены три правки:

1. **П. 3** — «среда» определена как только то, что не под git (локальный Docker, кеши, пустые
   тома БД, раннер); любая правка отслеживаемых файлов объявлена задачей; красный CI на `main`,
   вызванный содержимым репозитория, объявлен дефектом → сначала строка в Roadmap, потом ветка.
2. **П. 2 «Запрещено»** — добавлен запрет создавать ветку без id задачи из Roadmap; исключение —
   прямая явная инструкция пользователя, тогда ветка не-`task` (`docs/`/`chore/`/`ci/`), а
   основание фиксирует строка PR/коммита.
3. **Чек-лист «PR готов» (п. 12.4)** — добавлен пункт: ветка `task/<id>-*` ссылается на
   существующую строку Roadmap либо это не-`task` ветка по явной инструкции пользователя.

## 3. Что НЕ делаем и почему (отвергнутый вариант М2)

Рассматривался CI-job `flow-check`, краснеющий, если PR меняет файлы, а ветка не `task/<id>-*`
либо строки с этим id нет в Roadmap. Отвергнут:

- **Чтобы он ловил ровно класс инцидента, требуется ужесточить п. 12.2**: любая ветка с правками
  отслеживаемых файлов обязана быть `task/<id>-*`, а все прочие префиксы (`docs/`, `chore/`, `ci/`)
  — только внеплановая работа по инструкции пользователя, помеченная лейблом PR. Без лейбльной
  дисциплины job либо душит легитимные `docs/`/`chore/` (закрытие этапа, регистрация задачи 8.7,
  этот самый PR), либо пропускает всё.
- Лейбл ставит **пользователь** — новая ручная обязанность и новая точка отказа; цена (≈2 ч +
  поддержка + ложные красные) выше выгоды при текущем объёме.
- Правила читаются агентом перед началом работы, а чек-лист «PR готов» срабатывает до доклада —
  при текстовой формулировке нарушение видно раньше, чем его поймал бы CI.

Если класс нарушения повторится несмотря на М1, М2 возвращается в рассмотрение как задача с
строкой в Roadmap.
