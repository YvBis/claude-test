# PRD — 7.4: повышение/понижение до администратора

**Статус:** in progress (в `done` — только после мерджа)

**Оценка:** ~1.5ч (7.4a ~0.5ч, 7.4b ~1ч)

**User story:** artifacts/prd-taskflow-ru.md:63 + 85 — «назначать других
пользователей администраторами и убирать этот статус по желанию».

## Решения (зафиксированы до кода, визированы синьором)

- **Форма:** расширение существующего `PATCH /api/admin/users/{id}`
  (`Admin/`, IsGranted, гардрил покрывает). `UpdateUserDTO` получает
  опциональное `role` рядом с `is_active`; один update-путь.
- **Критичная дыра закрыта в плане:** ветвление строго на
  `null !== $dto->isActive` / `null !== $dto->role`, **никогда** truthiness —
  иначе role-only PATCH (`isActive=null`) молча заблокирует юзера
  (falsy → blockUser). Порядок: deserialize→400/422, getById→404,
  hasChanges→422, actor, затем `is_active`, затем `role`.
- **Один сервисный метод** `UserService::update(target, actor, ?bool
  isActive, ?Role role)`: оба гварда до мутации, один `flush()`.
  Частичный коммит недостижим (доказано синьором при любом порядке).
- **Гварды:** last-admin на demote (`countByRole`=1 + target активный
  админ → отказ); self-demote запрещён (403, симметрия с self-block).
  last-admin demote недостижим по HTTP (доказано) — safety invariant
  с юнит-покрытием, как в 7.2.
- **Идемпотентность:** promote уже-админа / demote уже-user → 200 no-op;
  проверка состояния в сервисе, доменные `promoteToAdmin/demoteToUser`
  не трогаем (их LogicException — контракт, покрыт `UserTest`).
- **Новые фабрики:** `SelfActionForbiddenException::changeRole()`,
  `LastAdminException::demote()`.
- **`role` в `UpdateUserDTO` — обязателен `Assert\Choice`** (иначе
  `Role::fromString` → 500, ловушка 7.3).
- **Граница с 7.3:** 7.3 минтит роль при создании, 7.4 — mutate
  существующего.
- **`createAdmin()`-удаление — ВНЕ 7.4** (отдельный chore-PR, уже смержен
  как #153).

## Скоуп

### 7.4a — сервис + гварды + юнит (~0.5ч)

- `UserService::update()` + фабрики исключений.
- Юнит: promote/demote меняют роль + flush; no-op на том же состоянии;
  self 403; last-admin demote 422; порядок гвардов (denySelf первым).

### 7.4b — DTO + контроллер + функц. + OpenAPI (~1ч)

- `UpdateUserDTO.role` с `Assert\Choice`.
- `Admin/UserController::update` — null-guarded ветвление.
- Функц.: promote/demote, no-op 200, self 403, last-admin demote (честно:
  приоритет self-guard, как 7.2), bad role 422, гость 401, юзер 403.
- OpenAPI: regen спеки + правка `OA\Patch`-аннотации (текст + тело с
  `role`). Набор кодов НЕ меняется — frozen-константы не трогаем.

## Карта ошибок

Гость → 401, не-админ → 403, валидация/роль → 422, битый JSON → 400,
неизвестный id → 404. Self → 403, last-admin demote → 422.
