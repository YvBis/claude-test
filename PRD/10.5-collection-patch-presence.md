# 10.5 — PATCH коллекции: присутствие поля, очистка и `theme`

## Дефект

`PATCH /api/collections/{id}` умел менять только «непустые» `name`/`description`/`image`:

- `UpdateCollectionDTO` сворачивал `''` → `null` в конструкторе, а `CollectionService::update` применял поле только при `null !== $dto->field`. То есть `null` означал «не передано», и очистить `description`/`image` было нельзя: `{"description":null}` неотличим от отсутствия ключа, `{"description":""}` в одиночку давал 422 «At least one field must be provided».
- `theme` в DTO отсутствовал, `Collection::changeTheme()` был недостижим, хотя `ARCHITECTURE.md` и OpenAPI обещали редактирование темы.

## Корень: сериализатор не различает «нет ключа» и «ключ = null»

Оба случая доходят до конструктора как `null`; Symfony Serializer не сохраняет факт присутствия ключа. Значит присутствие нужно взять из сырого тела запроса, а не из значений.

## Решение

1. **Контроллер** один раз декодирует тело и передаёт набор ключей в DTO:
   ```php
   $decoded = \json_decode($request->getContent(), true);
   $dto = $dto->withProvidedFields(\is_array($decoded) ? \array_keys($decoded) : []);
   ```
   `is_array`, а не `?:`: тела `"str"`, `5`, `true` — truthy-скаляры, и `array_keys()` на них бросил бы `TypeError` → 500. Не-объектное тело до этой точки либо уже отвергнуто сериализатором как 400, либо безопасно даёт пустой набор.
2. **`UpdateCollectionDTO`** получает `?string $theme` с `Assert\Choice(callback: [Theme::class, 'values'])` (прецедент — `FieldType`), флаги присутствия и `withProvidedFields(array $keys)`, который фильтрует ключи по известному набору `name|theme|description|image`. Неизвестные ключи игнорируются, как и раньше у нормализатора.
3. **Формула флага:** `hasX() = ключ присутствует || значение !== null`. Первая половина нужна PATCH-семантике (`null` очищает), вторая сохраняет поведение прямого конструирования DTO в юнит-тестах сервиса, где набора ключей нет.
4. **`Assert\Callback`** на методе: поле присутствует, но `null`, для `name`/`theme` → нарушение «cannot be null» → 422 через обычный DTO-путь. Описания и картинку `null` очищает, поэтому они в проверку не входят.
5. **`CollectionService::update`** применяет поле по флагу; `description`/`image` передают `null` прямо в `changeDescription(null)`/`changeImage(null)`; `name`/`theme` — только при non-null (валидация гарантирует, guard остаётся вторым эшелоном). Логика переименования и fan-out не менялась: `$renamed` зависит только от сравнения VO.
6. **OpenAPI:** `theme` с enum `books|games|movies|drinks`, `description`/`image` помечены `nullable: true`, описание PATCH объясняет «отсутствующий ключ — не менять, `null` — очистить, пустое/неизвестное тело — 422».

## Семантика `""`

Строка приводится к `null`:
- `description`/`image` — ключ присутствует, поэтому **очищает** (200). Раньше одиночный `{"description":""}` давал 422; поведение осознанно меняется.
- `name`/`theme` — 422 «cannot be null».

## Проверка

| Тест | Что доказывает |
|---|---|
| `testUpdateClearsDescriptionWhenNullIsExplicit` | сначала устанавливает описание, затем `null` очищает |
| `testUpdateClearsImageWhenNullIsExplicit` | то же для картинки |
| `testUpdateClearsDescriptionWhenEmptyStringIsSent` | `""` очищает |
| `testUpdateChangesTheme` | `{"theme":"games"}` меняет тему и возвращает её в ответе |
| `testUpdateRejectsUnknownTheme` | `{"theme":"garbage"}` → 422, в `details` есть `Invalid theme` |
| `testUpdateRejectsNullTheme` | `{"theme":null}` → 422 `Theme cannot be null` (раньше был 500) |
| `testUpdateRejectsNullName` | `{"name":null}` → 422 (раньше был 500) |
| `testUpdateRejectsUnknownOnlyBody` | `{"unknown":"value"}` → 422 «At least one field» |
| `testUpdateReturns422WhenNoChanges` | `{}` по-прежнему 422 |
| `CollectionServiceTest` (8 прямых конструкций) | флаг через non-null значение: поведение сервиса не изменилось |

Красное доказательство: убрать `withProvidedFields()` в контроллере → `{"description":null}` снова 422, тест очистки краснеет. Убрать `Assert\Callback` → `{"theme":null}` проходит сервисный guard и отдаёт 200 без изменения темы; тест ожидает 422 и краснеет.

## Принятые ограничения

- **Двойной `json_decode` тела.** Сериализатор декодирует его для DTO, контроллер — ещё раз для набора ключей. Тело небольшое, а альтернатива (кастомный денормализатор или sentinel-объект в union-типе) дороже: денормализатор ломает путь `MissingConstructorArgumentsException` → 422, sentinel конфликтует с `Assert\Length`.
- **Присутствие — свойство HTTP-запроса**, поэтому набор ключей извлекается в контроллере и передаётся в Application как данные, а не как зависимость от HTTP.
- **Поле `theme` меняется без fan-out поиска айтемов**: тема хранится только в документе коллекции, который переиндексируется на каждом `update` (`CollectionService:86`); документы айтемов денормализуют только имя коллекции.
