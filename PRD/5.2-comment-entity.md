# PRD 5.2 — Сущность Comment

## Статус

Выполнено (2026-09-16). Подзадача Этапа 5 (Социальное).

## Описание

Сущность `Comment` — текстовый комментарий пользователя к айтему. Один пользователь может оставить много комментариев айтему (UNIQUE нет). Контент — маркдаун-текст до 3000 символов; переводы строк и внутренние пробелы сохраняются. Комментарий редактируется владельцем (или админом — на уровне API, 5.5); правка обновляет `updatedAt`. Удаление — каскадом (айтем/пользователь удалены → комментарии удалены) либо явным `remove`.

## Требования (артефакты)

- `Comment`: `id`, `owner_id`, `item_id` (domain-model; `comment_id` в артефакте — опечатка, Roadmap 5.2 фиксирует `owner_id, item_id`).
- Связи: «Пользователь может иметь много комментов», «Айтем может иметь много комментов».
- PRD: «Пользователь может получить все комментарии айтема», «оставить комментарий к айтему», «поменять свой комментарий», «Администратор может поменять или удалить комментарий любого пользователя».

## Решения

- D1 (доступ): на уровне API (5.5); сущность/домен без правил доступа.
- `Comment.owner` = `ManyToOne User`, `Comment.item` = `ManyToOne Item` (консистентно с Collection/Item/Like; final-сущности → JOIN FETCH в read-методах).
- **Контент**: VO `CommentContent` (embeddable, immutable), длина **1..3000** (`mb_strlen`, UTF-8). Санитизация: `\r\n`/`\r` → `\n`; удаление control-символов `\p{Cc}` **кроме** `\n` и `\t`; `trim` краёв. Внутренние пробелы/новые строки **не схлопываются** (осознанное расхождение с `TagName`, где `\s+` → пробел). Маркдаун хранится как есть (рендеринг/экранирование — забота фронтенда).
- **UNIQUE нет** — пользователь может комментировать айтем многократно.
- **Индексы**: `idx_comment_item(item_id, created_at, id)` (списки комментов айтема) и `idx_comment_owner(owner_id, created_at, id)` (списки комментов пользователя; UNIQUE, который покрыл бы owner-префикс, отсутствует — в отличие от Like). Композитные с `created_at` и `id`, чтобы `ORDER BY created_at, id` обслуживался индексом без filesort (`id` явно; InnoDB добавляет PK и так). Замечание architect- и OpenRabbit-ревью.
- **Правка**: `changeContent()` + `touch()`, no-op при неизменном контенте (нормализованное равенство). Отдельного флага `isEdited` нет — достаточно `updatedAt`.
- Софт-делит не требуется.

## Декомпозиция

### S1 — VO + entity + интерфейс + unit-тесты (≤150 строк)

- `CommentId` VO (`src/Domain/Comment/ValueObject/CommentId.php`) — бинарный UUID (`UuidBinaryValue`), паттерн `LikeId`/`ItemId`.
- `CommentContent` VO (`src/Domain/Comment/ValueObject/CommentContent.php`) — см. решения.
- `Comment` entity (`src/Domain/Comment/Entity/Comment.php`) — id, owner (`ManyToOne User` CASCADE), item (`ManyToOne Item` CASCADE), content (embed), createdAt, updatedAt; `create(User, Item, CommentContent)`, `changeContent(CommentContent)` + `touch()`; `ClockAwareTrait`.
- `CommentRepositoryInterface` (`src/Domain/Comment/Repository/CommentRepositoryInterface.php`) — `save`, `remove`, `findById`, `findByItemId(ItemId, limit, offset)`, `findByOwnerId(OwnerId, limit, offset)`, `countByItemId`, `countByOwnerId`.
- Юнит-тесты: `CommentIdTest`, `CommentContentTest` (границы 1/3000, `\r\n`→`\n`, сохранение `\n`/`\t`, удаление прочих control, trim, длина; маркдаун-спецсимволы сохраняются), `CommentTest` (create/changeContent/touch/no-op/геттеры).

### S2 — Doctrine repo + миграция + интеграционные тесты + docs (≤150 строк)

- `DoctrineCommentRepository` — JOIN FETCH-цепочки (`c.owner`, `c.item → collection → owner`) против ghost-proxy final-сущностей; `IDENTITY`-сравнения бинарных UUID; порядок `createdAt ASC, id ASC` (детерминированный tiebreak).
- Миграция `Version<ts>` — таблица `comments`: `id VARBINARY(16)` PK, `created_at`/`updated_at DATETIME(6)`, `owner_id`/`item_id` VARBINARY(16) FK → users/items ON DELETE CASCADE, `content VARCHAR(3000)`, `INDEX idx_comment_item (item_id)`, `INDEX idx_comment_owner (owner_id)`, `DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci` (golden-style).
- Интеграционные тесты (MySQL): `CommentPersistenceTest` (persist+reload by id, каскад при удалении item, каскад при удалении user, правка меняет `content`+`updatedAt`), `DoctrineCommentRepositoryTest` (findById null, findByItemId пагинация+порядок, findByOwnerId + изоляция владельцев, countByItemId, countByOwnerId, remove). Для order-зависимых тестов — `MockClock` со сдвигом времени между созданиями (иначе tie на `createdAt` внутри одной микросекунды).
- Docs: `PRD/5.2-comment-entity.md` (этот файл), Roadmap 5.2, ARCHITECTURE (домен Comment), AssumptionLog.

## Критерии приёмки

- [x] `CommentId` + `CommentContent` (1..3000, newline-preserving) + `Comment` (create/changeContent/touch) + интерфейс (`save/remove/findById/findByItemId/findByOwnerId/countByItemId/countByOwnerId`) + Doctrine-реализация.
- [x] UNIQUE отсутствует; композитные `INDEX (item_id, created_at)` + `INDEX (owner_id, created_at)`.

- [x] Каскад: удаление айтема/пользователя → комментарии удалены.
- [x] Правка меняет `content` и `updatedAt`; no-op при неизменном контенте.
