# PRD 4.7 — API-эндпоинт тегов (список/поиск)

## 1. Description

`GET /api/tags?search=&limit=&offset=` — поиск/список существующих глобальных тегов для выбора при проставлении айтему (autocomplete). Теги создаются не через API, а опосредованно через айтемы (`TagService::resolveByNames`); эндпоинт — read-only.

Покрывает user story «выбор тегов из уже существующих при проставлении айтему» (список для UI).

## 2. Requirements

- `artifacts/prd-taskflow-ru.md`: story про теги (глобальные, переиспользуемые, выбор из существующих).
- `artifacts/domain-model-taskflow-ru.md`: Tag — глобальный, `name` уникален регистронезависимо (collation `utf8mb4_0900_ai_ci`).
- `artifacts/technical-requirements-taskflow-ru.md`: REST, Clean Architecture, слои.

## 3. Scope

- `GET /api/tags` — список тегов, опциональные фильтры `?search` (подстрока, ci), `?limit`, `?offset`.
- Доступ: только аутентифицированные (`IS_AUTHENTICATED_FULLY` — теги нужны в auth-флоу тегирования). Аноним → 401.

Out of scope: создание/удаление/переименование тегов, админ-операции, публичный доступ.

## 4. Endpoint

`GET /api/tags`

| Параметр | Тип | Default | Валидация |
|---|---|---|---|
| `search` | string | — | свободный текст (НЕ через `TagName` — тот требует ≥2 символов); trim + strip control-символов; пустой → все теги |
| `limit` | int | 50 | 1..100 |
| `offset` | int | 0 | ≥0 |

Ответ: `200` + bare-массив `TagDTO[]` (`{id, name}`), `ORDER BY name ASC`. Ошибки: `401` (аноним), `400` (невалидный limit/offset, конверт как у айтемов).

## 5. Decisions (D1–D4)

- **D1** — `search` = подстрока `LIKE %term%` (ci-коллация), wildcards `%_` экранируются. (Консистентно с фильтром `?name` у айтемов.)
- **D2** — доступ auth-only (catch-all `^/api` → `IS_AUTHENTICATED_FULLY`), спец-правило не нужно.
- **D3** — default limit 50 (как у айтемов/коллекций).
- **D4** — ответ bare-массив `TagDTO[]`.

## 6. Decomposition

### S1 — Repository search + Service (≤150 строк, ~1.5ч)
- `TagRepositoryInterface::search(?string $term, int $limit, int $offset): array` + docblock.
- `DoctrineTagRepository::search` — `t.name.value LIKE :term` (escape `%_`), `ORDER BY t.name.value ASC`, `setMaxResults`/`setFirstResult`.
- `TagService::listTags(?string $term, int $limit, int $offset): array<Tag>` — нормализация term (trim, strip `\p{Cc}`, `''` → null), делегирует в repo.
- Интеграционные тесты (MySQL): пустой терм → все; подстрока ci (`'ook'` → `Books`); escape `%`/`_`; пагинация; порядок ASC.

### S2 — Controller (≤150 строк, ~1.5ч)
- `TagController` — `GET /api/tags`: разбор query, валидация limit/offset (1..100, ≥0) → `400 {"error":"Validation failed","details":[...]}`, `\InvalidArgumentException` (UUID не нужен) → 400, `TagDTO::fromEntity` + `toArray()`, OA-аннотации (`#[OA\Get]` с `TagDTO[]`).
- OpenAPI: `components` для `Tag` — есть? Проверить; если нет — добавить в `api_doc.yaml` (nelmio).

### S3 — Functional tests + docs (≤150 строк, ~1.5ч)

## 8. Notes / Risks

- Поиск-терм свободный (НЕ `TagName`): min-длина 1 для поиска; TagName применяется только при СОЗДАНИИ тега через айтем.
- Риск: `LIKE` на большой таблице — индекс по `name` есть (UNIQUE); подстрока `%term%` не использует индекс (scan) — приемлемо для MVP (теги редкие). fwd-note.
