## Шаг 1 — Smoke против собранного стека (§9)

**Почему не «wait healthy».** Хелсчек есть только у `db`; `app` и `nginx` его не имеют
(`docker-compose.yml:29-30,45-53`, решение 8.7). `up -d` возвращает управление раньше, чем
php-fpm/nginx начинают отвечать, поэтому готовность проверяется **опросом
`curl -fsS http://127.0.0.1:8000/health`** — тем же сигналом и тем же адресом, что в
job'е `e2e` (`ci.yml:327`). `127.0.0.1`, а не `localhost`: на хосте, где `localhost`
резолвится сначала в `::1`, опрос против IPv4-bind не позеленеет никогда. **Опрос обязан
валидировать тело (`"status":"ok"`), а не только код ответа, и иметь запас по времени:**
в этом окружении фатал PHP пришёл с HTTP 200, а первый запрос после свежего `var/` собирает
кэш ~13 с (урок и ремонт среды — `AssumptionLog.md`, запись 2026-10-18).

**Состав:** `docker compose down && docker compose up -d` → poll `/health` до 200 → миграции
актуальны → journeys (`bru run --env local --exclude-tags=smoke`) → smoke
(`bru run smoke --env local`). Dev-данные не чистим: smoke-пользователи накапливаются, это
решение 8.2 (`PRD/8.2-smoke-bruno.md`). Bru-окружение остаётся на `localhost`
(`tests/E2E/environments/local.bru:2`) — это отдельный от опроса адрес, менять не нужно.

**Отчёт:** «12/12 journeys + 5/5 smoke».

**Красный прогон — триаж, не автоматическая задача.** Сначала классификация по `CLAUDE.md`:
- среда (нет `bru`, вычищенный том Meilisearch → фильтрованный поиск 500 до `search:reindex`,
  занятый порт 8000) — чиним среду, строки не заводим;
- дефект трекаемых файлов — сначала строка в Roadmap + PRD, потом фикс; внутри 8.8 фикс не
  едет (скоуп).
