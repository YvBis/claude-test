# PRD 8.3 — Аудит покрытия по слоям (domain/application, гейт 80%)

**Статус:** done
**Задача Roadmap:** 8.3 — Аудит покрытия: 80% на слоях `domain`/`application`
**Оценка:** ≤ 2 человеко-часов, ~60 строк (скрипт-гейт + доки)

## 1. Исходное состояние

- Глобальный гейт есть: `scripts/coverage-gate.php` читает `var/coverage/clover.xml`
  (project-level `<metrics>`), минимум `COVERAGE_MIN` (дефолт 80). Факт: **98.12%** строк
  глобально — запас огромный.
- Послойного измерения нет: гейт смотрит только project-метрики, `src/Domain` и
  `src/Application` отдельно не проверяются. Строка 8.3 требует именно послойный аудит
  против тех же 80%.

## 2. Состав

1. **Измерение:** расширить `scripts/coverage-gate.php` (или рядом `coverage-layers.php`,
   решение по месту — не плодить сущности без нужды) послойным разбором того же
   `clover.xml`: агрегация по префиксу пути файла (`src/Domain/`, `src/Application/`,
   остальное — для отчёта, без гейта). Формат вывода: таблица слой → statements/covered/%.
2. **Гейт:** каждый из `Domain`, `Application` ≥ 80% (тот же `COVERAGE_MIN`), иначе exit 1
   с явным указанием слоя. Остальные пути — только отчёт.
3. **Проводка:** тот же composer-шаг, где сейчас `coverage-gate` (проверить `composer.json`
   `coverage:gate` и вызов в CI) — послойная проверка должна выполняться там же, а не новым
   job'ом.
4. **Документация:** запись в `AssumptionLog.md` (замер по слоям + решение о гейте);
   строка 8.3 → done; счётчики (этап 8: 4/7, Итого 51/54).

## 3. Что НЕ входит

- Поднятие глобального порога выше 80% — не предмет строки.
- Покрытие `Infrastructure` гейтом — адаптеры/контроллеры покрыты функционально; гейтить
  их отдельно не требуется (только отчётная строка, если бесплатно).
- Infection/мутации — задача 8.4, не смешивать.

## 4. Риски и честность

- Clover-метрики по файлам — точный источник (php-code-coverage пишет per-file
  `metrics`), агрегация детерминирована; флейка нет.
- Если какой-то слой < 80% (маловероятно при 98% глобально) — сначала дописать тесты,
  затем гейт; пустой гейт не коммитить.

## 5. Доказательство

Зелёный прогон с таблицей слоёв в выводе + красный контроль: временно завышенный
`COVERAGE_MIN=100` (или обрезанный clover-фикстурой юнит-тест скрипта) должен ронять гейт —
по образцу guard-тестов проекта (красный/зелёный до коммита).
