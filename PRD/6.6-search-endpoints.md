# Задача 6.6 — Поисковые эндпоинты

**Статус:** done (смержен в PR #146)

## Цель

Открыть поиск наружу: два публичных GET-маршрута поверх read-порта, с валидацией,
пагинацией, конвертом ошибок и актуальной OpenAPI-спекой.

## Решения (приняты на плане, синьор)

1. **Гидратация — документы, не БД.** Engine-документы оборачиваются в Application DTO
   (именованный тип, тот же `toArray()`), без похода в БД. Сиротская политика отложена
   этапом; гидратация форсировала бы её досрочно.
2. **Мёртвый движок на чтении — 500.** Read-адаптер ничего не ловит; исключение идёт в
   `kernel.exception`, наружу — голый `{error}`. Как при упавшем MySQL.
3. **Пустой `q` — обязателен, blank → 400.** Match-all — дамп корпуса; для листинга есть
   свои эндпоинты.
4. **Фильтры:** items — `owner` (uuid|`me`), `collection_id`, `tags[]` (AND);
   collections — `owner`, `theme`. Без `owner` — глобально.
5. **HEAD — поддержать**, добавить в `security.yaml`, покрыть тестом.
6. Write-порт и read-порт — разные интерфейсы.
