# PRD fwd-6b — lock the load-bearing joins, keep the projection lever

**Статус:** docs + test locks (2 докблока в интерфейсах, 2 докблока в тестах, 1 ассерт в
каждом репозиторном тесте, 1 строка Roadmap, запись в AssumptionLog). Поведение не
меняется, запросы не меняются, схема не меняется.

## Контекст

`fwd-6` (2026-10-01) закрыл N+1 по тегам двухзапросным batch'ем и оставил в Roadmap
строку `fwd-6b` — «рассмотреть одно-запросную проекцию для списков, когда эндпоинт
вырастет за MVP». Строка содержала два неверных утверждения, оба унаследованные:

1. «`listByItem` в `LikeRepository`/`CommentRepository`: **4-join** `withAll()`» —
   после fwd-5 джойнов два (`item`, `item.collection`), а владельца как ассоциации
   больше не существует;
2. «`ItemService::replaceTags` (PATCH) на них завязан» — возражение против проекции,
   которое снимается замером.

## Гипотеза, которую надо было опровергнуть первой

Джойн `item.collection` казался мёртвым: ни один потребитель в `src/` не читает
`Item::getCollection()` по социальному контенту. Первоначальный план fwd-6b предлагал
снять джойн.

### Проба 2026-10-04

Ветка `probe/fwd-6b-collection-join`, снят **только** джойн `collection` в обоих
`withAll()` (джойн `item` оставлен), затем тесты и `ci:all`:

| Прогон | Результат |
|--------|-----------|
| `tests/Infrastructure/Comment` + `tests/Infrastructure/Like` | 23 теста, **4 errors** |
| `ci:all` | exit 2 — 856 тестов, **4 errors + 21 failures** |
| после отката | 61 тест, OK |

Ошибка единообразна: `Cannot generate lazy ghost: class "App\Domain\Collection\Entity\Collection"
is final` — из `ObjectHydrator.php:443` через `ProxyFactory.php:283`.

### Что это значит

1. **Джойн держит не читатель, а гидрация.** `ObjectHydrator` обязан разрешить
   `Item.collection` в момент подтягивания `Item`, а `final` (решение review-6) гостя
   не даёт. Снятие джойна даёт throw во время гидрации, а не лишний запрос.
2. **«Нет вызова геттера» ≠ «нет зависимости».** Это и есть механизм, который
   первоначальный план принял за овер-фетч.
3. **Холодный функциональный читатель существует.** `CommentPersistenceTest` читает
   `getItem()->getCollection()` после `em->clear()` — то есть именно по пути, который
   ломает снятый джойн. Первичный греп искал потребителей `getCollection()` на
   социальном read-пути, но шёл только по `src/`, и дал ложный ноль: в `src/` есть
   читатели (`ItemController:309` PATCH, `ItemController:355` DELETE), просто они идут
   через одиночный `findById` и к социальному джойну отношения не имеют. Вывод «читателей
   нет» был ложен именно в своей области, а не из-за непроверенных тестов. Урок честнее
   формулировать так: искать надо по конкретному пути запроса, а не по символу.

### Уточнение к записи fwd-16

`PRD/fwd-16-owner-hydration-invariant.md:98-104` фиксирует тот же вывод, но заявляет
«падают три теста». Фактический охват — **25** (4 + 21 каскадом в `CommentControllerTest`:
список, PATCH, DELETE, админ-пути). Запись по сути верна, но неполна по охвату; здесь
зафиксирована полная картина.

## Решения

| Вопрос | Решение | Основание |
|--------|---------|-----------|
| Снимать ли джойн | **Нет** | проба дала 4 errors + 21 failures |
| Частичные селекты вместо join | **Нет** | ORM 3 их удалил |
| `fetch: EAGER` на `Item.collection` | Рассмотрено и отклонено | лишний read на каждую загрузку, хуже явного join |
| Нативные lazy-объекты | Внешний триггер, задачи нет | PHP 8.4 / ORM 4; сейчас проект на PHP 8.3 |
| Проекция, отдающая массив/скаляры | Остаётся кандидатом, под триггером | такой результат не проходит через `ObjectHydrator`, поэтому пробой не опровергнут |
| Возражение про `replaceTags` | **Снято** | `ItemController::update` → `ItemService::getById` → одиночный `findById`; `replaceTags` приватен и зовётся только из `update`; списки кормят только чтение |

## Скоуп

1. **Roadmap, строка `fwd-6b`** — очередь, а не лог: состояние обеих частей, указатель на
   этот PRD, измеримый триггер, оценка. Правки фактов: 2 джойна вместо 4 (владелец —
   колонка с fwd-5), возражение про `replaceTags` снято, цитата на
   `PRD/fwd-8-counters-batch.md`, а не на fwd-6 PRD. Историю проб и отклонённых
   альтернатив держит AssumptionLog, сюда она не дублируется.
2. **Два докблока интерфейсов** — снять обещание «collection owner hydrated»: с fwd-5
   владелец коллекции не ассоциация, джойнить его нечего. Оставить гарантию: `item` и
   `item.collection` гидратированы, потому что `final` не проксируется в ORM 3.
3. **Два докблока тестов** — «no consumer reads today» заменить механикой гидрации,
   иначе они противоречат соседнему ассерту.
4. **Ассерт на гидрацию коллекции** в обоих репозиторных тестах — плюс докблок, честно
   описывающий границы замка (см. ниже).
5. **AssumptionLog** — запись о пробе и чеклист для `[future]`-строк.

## Границы замка (проверено ревью)

`Collection` объявлена `final`, поэтому на текущем стеке (ORM 3.7.2, PHP 8.3,
`nativeLazyObjects` выключен) коллекция не может быть неинициализированным призраком, и
`isUninitializedObject()` по ней всегда `false`. Значит новый ассерт **сегодня не может
упасть сам по себе** — сегодня джойн защищает сам факт успешного запроса: без джойна
гидрация бросает исключение, и тест краснеет до ассерта. Ассерт оставлен потому, что
при `nativeLazyObjects` final-класс становится ghost'ом, и проверка начнёт иметь смысл —
не хочется тогда возвращаться и дописывать её. Называть это «замком джойна» было бы
преувеличением; в докблоках так и написано.
