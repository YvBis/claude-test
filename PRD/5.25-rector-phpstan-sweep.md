## Контекст

`PRD/5.25-major-sweep.md` делил 5.25 на 4 PR. Senior-review свипа доказал
зависимый узел: `rector/rector` требует `phpstan/phpstan` обычной
зависимостью во всём 2.x (`2.0.0 → ^2.0.1`, `2.6.7 → ^2.2.14`), а корень пинит
`^1.12` и расширения `^1.x`. Composer не держит две версии одного пакета —
значит PR-2 и PR-3 не разделяются ни в каком порядке (rector 1.2.10 требует
`phpstan ^1.12.5`, подъём phpstan без rector ломает `composer install`).
**Решение (пользователь, 2026-09-29): один свип, один сквош-коммит.**

## Гипотезы (фиксируются до кода)

- H1. include-пути `phpstan.neon:2-4` выживают в 2.x: `extension.neon`
  (symfony, doctrine) и `rules.neon` (deprecation-rules) есть в корнях 2.x.
  Проверено по деревьям до кода; поведение — срез A.
- H2. doctrine 2.x выбирает baseline под версию: в 2.x есть
  `phpstan-baseline-dbal-4.neon` / `phpstan-baseline-orm-3.neon`
  (против DBAL 4.4 / ORM 3.7 в замке). Срез A измеряет, какой baseline
  реально подхватывается.
- H3. `PhpVersion::PHP_83` и форма билдера
  (`configure/withPaths/withSkip/withSets/withPhpVersion`) живы в rector 2.x.
  Проверяется `rector validate-config` в срезе C.
- H4. Находок `rector:dry-run` после бампа будет ≤5 (порог пользователя;
  считать находки, не файлы). Больше или правило трогает семантику →
  точечный skip с причиной, а не молчаливый `rector:fix`.
- H5. `rector validate-config` имеет контракт exit 0/1 и форму json из
  release notes 2.6.7. Документации команды нет — контракт измеряется в
  срезе C (чистый конфиг, транзиентное deprecated-правило, форма json).
  Без трёх чисел гейт не подключается.

## Измерения по ходу

- **Срез 0 (bleeding edge на 1.12.33): 1 находка.**
  `Domain/User/ValueObject/PasswordHash.php:41` —
  `@var string|false` не подтип нативного `non-empty-string`.
  include откачён сразу после замера, в замок не входит.

- **Срез C: контракт `validate-config` измерен (реальные коды, не `$?`).**
  Чистый конфиг: exit **0**, `[OK] Config is valid`. Грязный (транзиентно
  зарегистрированное deprecated-правило `FluentSettersToStandaloneCallMethodRector`):
  exit **1**, WARNING называет правило + `[ERROR] 1 config issue found`.
  JSON чистого: exit 0, `{"valid": true, "issue_count": 0}`. Несуществующий
  путь в `withSkip` НЕ ловится (exit 0) — «invalid skips» из release notes
  означает что-то другое; гейт ловит deprecated-правила, это доказано.
- **Срез C: `SetList::PHP_83` → `withPhpSets()`.** Старый стиль на 2.6.7
  даёт WARNING (per-version set deprecated) при exit 0. Контрольный замер:
  старый стиль — 17 файлов, новый — 45. `withPhpSets()` без аргументов
  резолвит нижнюю границу `>=8.3` → 8.3 (детерминированно), разница —
  новая level-система правил вместо урезанного файла php83.php.

- **Срез D: находки применены, гейт подключён.** 45 файлов >> порога 5 →
  точечные skip'ы с причинами в `rector.php`: constructor-promotion (24
  переписа конструкторов сущностей — не скоуп бампа), сортировка
  named-args (20, авторский порядок OA-атрибутов — churn). По ходу найден
  4-й skip: `RemoveDefaultValueFromAssignedProperty` снял `= null`/`= true`
  с ORM-полей (`User::$isActive`, `Collection::$image/$description`) —
  Doctrine гидратирует мимо конструктора, дефолты страхуют недошедший
  доступ (uninitialized Error вместо значения); оба файла откачены.
  Остаток (~7 правил: Stringable, catch-var, strict_types, arrow-callable,
  multi-catch, readonly `$details`) применён через `rector:fix`, цикл
  `phpcs:check` (0) + `phpstan` (OK) + `dry-run` (done) закрыт.
  Гейт: скрипт `rector:validate-config` + шаг в `ci:static:quality` сразу
  после `@openapi:fresh` + `RectorConfigTest` (2 теста, поиск по `name`).

- **Срез E: двустороннее доказательство.** `validate-config`: чистый —
  exit 0, грязный (deprecated-правило) — exit 1 (замерено реальными
  кодами, не `$?`). `dry-run` на 2.6.7: красный до фикса (45 файлов,
  error code 2) → зелёный после (`Rector is done!`).

- **Срез A: замок ровно по плану.** Установлено: phpstan 2.2.16,
  doctrine 2.0.28, symfony 2.0.20, deprecation-rules 2.0.5, rector 2.6.7
  (все `composer show -i` совпали с целевыми). Находок `composer phpstan`:
  **2** — (1) `PasswordHash.php:41` (предсказана срезом 0, совпадение
  точное); (2) `SocialContentVoter.php:26` — `missingType.generics`
  (Voter без TAttribute/TSubject; bleeding edge её не дал).
