# PRD — 7.5: айтемы чужого владельца + доказательство admin-override

**Статус:** in progress (в `done` — только после мерджа)

**Оценка:** ~1.5ч (7.5a ~1ч, 7.5b ~0.5ч)

**User stories:** artifacts/prd-taskflow-ru.md:25 + 33 («смотреть и управлять
чужими коллекциями и айтемами как владелец»); критерии приёмки 113–118.

## Установлено до кода (син:ор, синьор визировал)

- Мутации чужих коллекций/айтемов админом уже работают
  (owner-or-admin); модерация комментариев/лайков — тоже; чтение
  коллекций чужого (`?owner=`) публично; чтение айтема/коллекции по id и
  айтемов коллекции открыто.
- **Единственный пробел:** `GET /api/items?owner={uuid}` отсутствует —
  критерий 113 («все айтемы любого пользователя») не выполнен для айтемов.
- Создание коллекции за другого (строки 25/33) вне 113–118 — исключено из
  7.5 навсегда решением владельца (син:ор подтвердил неучастие).
- Асимметрия осознанная: `collections?owner=` публично, `items?owner=` —
  только аутентифицированные (решение владельца; гость видит данные через
  collections/items-по-id и так, нового публичного surface нет).
- `owner=me` не поддерживаем — зеркалим коллекции (только UUID).

## Решения

- `?owner` парсится **внутри `listOwn`**, не в общем `parseFilters`
  (син:ор: иначе `GET /api/collections/{id}/items?owner[]=x` молча сменит
  «игнор» на 400).
- Сырой query-bag (fwd-25): не-скаляр/битый owner → 400 нашим конвертом.
  Несуществующий owner → 200 пустой список (прецедент коллекций).
- Без owner — свои (поведение не меняется). Фильтры name/tags[] и
  пагинация применяются к owner-списку.
- Гость → 401 (catch-all, без правки security.yaml). HEAD — через GET-роут.
- Сервис/репо без изменений (`ItemService::listByOwner`, `findByOwnerId`).
