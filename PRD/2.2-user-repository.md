# PRD: Task 2.2 — UserRepository + Migration

## 1. Цель

Создать репозиторий для сущности User с CRUD-операциями и миграцию БД для таблицы `users`.

## 2. Требования

### Интерфейс репозитория (Domain слой)
```php
interface UserRepositoryInterface
{
    public function save(User $user): void;
    public function remove(User $user): void;
    public function find(UserId $id): ?User;
    public function findByEmail(Email $email): ?User;
    public function findAll(): array;
    public function existsByEmail(Email $email): bool;
}
```

### Реализация (Infrastructure слой)
- Doctrine ORM repository с кастомными методами
- Наследует `ServiceEntityRepository`

### Миграция
- Таблица `users` с колонками:
  - `id` (binary(16), PK) — UUID v7
  - `email` (varchar(255), unique) — Email VO
  - `password_hash` (varchar(255)) — PasswordHash VO
  - `role` (varchar(20)) — Role VO (user/admin)
  - `name` (varchar(100)) — имя пользователя
  - `is_active` (boolean, default true) — статус активности
  - `created_at` (datetime_immutable) — создана
  - `updated_at` (datetime_immutable) — обновлена
- Индексы: `idx_user_email`, `idx_user_is_active` (как в Entity)

## 3. Тесты (Unit)

### Domain слой
- Тест интерфейса: мок репозитория, проверка сигнатур

### Infrastructure слой
- Интеграционные тесты с реальной БД (через `KernelTestCase`):
  - `save()` + `find()` roundtrip
  - `findByEmail()` возвращает пользователя
  - `existsByEmail()` возвращает true/false
  - `findAll()` возвращает все пользователи
  - `remove()` удаляет пользователя
