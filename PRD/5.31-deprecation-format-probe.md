# 5.31 — Runtime-зонд дрейфа формата депрекейшенов

## Проблема

Шаг `unit-tests` грепает лог прогона (`grep -qE 'triggered [0-9]+ deprecation'`) и
поднимает `::warning::`. Строка принадлежит выводу самого PHPUnit
(`ResultPrinter`), поэтому апгрейд PHPUnit с переформулировкой вывода молча
отключит предупреждение: джоб зелёный, депрекейшены невидимы. Тот же класс
silent no-op, из-за которого появилась 5.24.

## Решение

Отдельный CI-шаг `Probe deprecation output format` после гейта запускает
`scripts/deprecation-format-probe.sh`:

1. Скрипт извлекает паттерн из `grep -qE '<pattern>'` шага suite (единственный
   такой grep в `ci.yml` — скрипт падает, если совпадений не ровно одно, так
   что будущий второй grep не уведёт зонд молча) — проверяется то, на что
   опирается пайплайн, а не рукописная копия.
2. Два дочерних прогона `php bin/phpunit --no-configuration --colors=never
   --display-deprecations <фикстура>` на коммитированных фикстурах
   `tests/Fixtures/Deprecation/`:
   - `DeprecationTriggerFixture` (один `trigger_error(E_USER_DEPRECATED)`,
     без `@` — подавление PHPUnit не видит, 5.24) обязан матчить паттерн;
   - `DeprecationCleanFixture` обязана НЕ матчить (ловит future-расширение
     регулярки до бессмысленно широкой).
3. Exit code обоих детей обязан быть 0: `--display-deprecations` остаётся
   отображением, а не гейтом.

Пины против рекурсии — кодом перед каждым запуском, не комментарием: ребёнок
без `--no-configuration` загрузил бы `phpunit.xml.dist` и ушёл в suite
(включая сам зонд), ребёнок с каталогом вместо файла запустил бы лишнее.
Проверяются наличие `--no-configuration`, отсутствие `-c`/`--configuration` и
читаемость явного пути к файлу фикстуры.

Фикстуры без суффикса `Test` и вне всех testsuite: `TestSuiteLoader`
выводит имя класса из имени файла и требует совпадения суффикса имени
(`vendor/phpunit/phpunit/src/Runner/TestSuiteLoader.php:48,67`), суффикс
`Test` для этого не нужен, а с ним файл рисковал бы подбором будущим
рекурсивным suite. `--bootstrap vendor/autoload.php` не нужен: `bin/phpunit`
уже подключает автолоадер (`vendor/phpunit/phpunit/phpunit:50`).

Wiring шага пинится статическим тестом
`DeprecationConfigTest::testDeprecationFormatProbeStepRunsTheProbeScript`
(ровно один шаг, без `continue-on-error`, скрипт и обе фикстуры существуют):
снятый шаг роняет guard, а не заметается.

## Почему отдельный шаг, а не тест в suite

Изначальный план — зонд-тест внутри suite. Замер в Docker-контейнере: один
дочерний прогон 5.8 с (бут фреймворка, не выполнение), два — ~12 с поверх
~270 с шага. Бюджет зонда был 5 с с уговором «обсуждаем при превышении»;
решение пользователя — отдельный CI-шаг, нулевая цена для каждого локального
`composer ci:all`.

## Верификация

- `composer ci:all`: 706 tests / 2095 assertions, exit 0.
- Скрипт в контейнере: `probe: OK` (паттерн извлечён, триггер матчит,
  чистая — нет).
- 5 негативных проб с откатом, все кусаются:
  1. сломанная регулярка в `ci.yml` → `did NOT produce the line`, exit 1;
  2. убранный `trigger_error` → exit 1;
  3. loose-паттерн `test` → `too loose`, exit 1;
  4. снятый шаг → guard-тест падает (5 assertions, 1 failure);
  5. второй `grep -qE` в `ci.yml` → `expected exactly one`, exit 1
     (review-нит senior/architect: `head -n 1` молча брал первое совпадение).
- `bash -n` скрипта чист.

## Вне скоупа

- Жёсткий гейт `--fail-on-deprecation` — задача 5.25.
- Зонд дрейфа других greppable-строк CI (например `failure\|cancelled` в
  `ci-summary`, см. 5.27) — отдельные задачи по мере появления.
