# Задача 6.3 — Реальный движок в CI и изоляция тестов

**Статус:** in progress

## Цель

Доказать против настоящего v1.54, что документы и настройки 6.2 принимаются движком,
и дать сьюту движок в CI. Мок-тесты 6.2 — каркас контракта; эта задача — проверка
приёмки. Плюс конвенция очистки, потому что у поиска нет аналога DAMA-отката.

## Критерии приёмки

- [x] Сервис `meilisearch:v1.54` в job `unit-tests` (`MEILI_MASTER_KEY`, `MEILI_NO_ANALYTICS`, health на `/health`)
- [x] Forced `MEILISEARCH_ITEMS_INDEX=items_test` / `MEILISEARCH_COLLECTIONS_INDEX=collections_test` в `phpunit.xml.dist`
- [x] Базовый `EngineBackedSearchTestCase`: клиент через `test.meilisearch_client`, адаптер руками, `ensureIndexes()` + wipe в setUp
- [x] Настройки приняты: прочитанные настройки обоих индексов равны `IndexSettings`
- [x] Документ айтема: запись через адаптер → чтение через клиент совпадает с `toArray()`
- [x] Документ коллекции: то же
- [x] Гард паритета тегов CI/compose + forced-индексов
- [x] `ci:all` зелёный локально; остановка движка роняет только engine-тесты
- [x] `coverage:gate` ≥ 80% (явный запуск)
- [x] `openapi.json` байт-в-байт
- [x] Три ревьюера дали явный вердикт до коммита: senior SHIP-WITH-NITS, архитектор APPROVE,
      техлид MERGE-WITH-FIXES; внесены assertEquals на roundtrip, catch ExceptionInterface в
      полле, гард пустых имён индексов, уточнение комментария про force, сверка Roadmap;
      отклонён `@group engine` с исключением из дефолтного прогона (CI обязан гонять эти тесты,
      локально движок требуется по README)

| Сабтаск | Объём | Оценка |
|---------|-------|--------|
| 6.3a | Инфра + гарды: PRD, сервис в CI, forced-индексы, гард паритета, README | ~1ч |

Два коммита, один PR. Тесты снова перевалят за эвристику 150 строк — фиксируется, как в 6.1/6.2.

## Решения

1. **Неймспейс фиксированный, не per-run.** `items_test`/`collections_test` всегда. CI-сервис
   эфемерен (уникальность на прогон там ничего не покупает), локально стабильные имена
   переиспользуют два индекса вместо свалки. Формулировка Roadmap «на прогон» толкуется как
   «отдельно от продакшена», а не «уникально на запуск» — принято владельцем.
2. **Очистка — wipe документов в setUp базового класса.** DAMA делает откат транзакции для БД;
   у поиска транзакций нет, поэтому каждый engine-тест начинается с пустых индексов (удаление
   документов обоих индексов + ожидание). Сами индексы живут между классами.
3. **Порт не биндится.** Алиас `SearchIndexerInterface → адаптер` — 6.4 с первым потребителем.
   Тест получает движок через `test.meilisearch_client`, адаптер строит руками. Конкретного
   публичного алиаса адаптера не заводится.
4. **Ключ хардкодится** (`masterKey123` в сервисе CI), прецедент mysql. Не секрет: продакшена
   нет, а секрет сломал бы fork-PR (там секретов нет — ключ разошёлся бы с fallback в phpunit).
   `MEILI_ENV` не ставится.
5. **Команды провижининга нет.** Тесты вызывают `ensureIndexes()` сами; команда reindex в 6.4
   вызовет его первой (идемпотентен).
6. **Переменных CI для Meilisearch нет.** Non-forced fallback в phpunit уже даёт раннеру
   правильный хост и ключ; дублировать в job — второй источник истины.
7. **Таймаут 30с достаточен.** Health-ретраи гейтят старт шагов (10×5с), движок тёплый;
   каждая задача — доли секунды.

## Вне скоупа

- Маршруты, OpenAPI — 6.6
- Bulk-reindex — 6.5

## Открытый вопрос (разрешить до написания roundtrip-теста)

Адаптер возвращает void и выбрасывает task uid, поэтому «записал → сразу прочитал» может
гонять. Перед тестом прочитать vendor 1.17.0 и выбрать: ожидание по задачам индекса
(`getTasks` + `waitForTask`) или ограниченный poll `getDocument`. Если чистого способа нет —
честный fallback: документ кладёт сам клиент (доказательство приёмки payload), форма запроса
остаётся за мок-тестом. «Нет warning в логе» доказательством приёмки не считается (асинхронные
падения задач не логируются).
