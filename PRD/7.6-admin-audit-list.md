## Установлено до кода (син:ор, синьор визировал)

- Глобального листинга нет: порты — только `findByItemId`/`findByOwnerId`;
  списки — только «свои» и по айтему. Единственная новизна — `findAll`.
- **Админ-UI не реализуем** (фронтенд пишет отдельная команда;
  основание — `artifacts/prd-taskflow-ru.md:10` «только РЕСТ апи»). Контракт
  проектируем «под UI» (есть `item_name`). Строка Roadmap 7.6
  переформулируется без UI.
- `withAll` обязателен в `findAll` (final-сущности, DTO читает `getItem()`).
- `#[ORM\Index]` в сущностях — в том же коммите, что миграция (ловушка fwd-5).
- `AdminGuardTest` покрывает новые роуты автоматически (фильтр по пути
  `/api/admin`); правок теста не нужно.
- OpenAPI/frozen — в **каждом** подшаге (иначе `openapi:fresh` упадёт).
  Коды обоих роутов `['200','400','401','403']`.

## Решения

- **Контракт:** `GET /api/admin/comments` и `GET /api/admin/likes`,
  `#[IsGranted('ROLE_ADMIN')]`, `Admin/`, пагинация, порядок
  `created_at DESC, id DESC`. Ответы — `CommentDTO[]`/`LikeDTO[]`.
- **`item_name` — в общие DTO** (не audit-DTO): читается прямо из
  джойнутого item (`withAll` уже `addSelect(item)`), лишних запросов нет.
  Радиус: by-item/by-owner ответы тоже получат `item_name` (аддитивно);
  правки: schema-блоки `api_doc.yaml` + frozen `schemas.Comment`/`Like`.
- **Индекс `(created_at, id)` на `comments` и `likes`** + EXPLAIN без
  filesort. Отклонение от fwd-27 (там принят filesort) зафиксировано здесь.
  Placement: comments — 7.6a; likes — 7.6b.
- MVP без фильтров (owner/item) — отдельный триггер. Переноса владения нет.
