# PRD — 7.2: блок/разблок/удаление пользователей

**Статус:** done (смержен в PR #151)

**Оценка:** ~1.5ч (7.2a ~1ч с fan-out и гардами, 7.2b ~0.5ч)

**User stories:** artifacts/prd-taskflow-ru.md:59-61 (блокировать,
разблокировать, удалить).

## Решения (зафиксированы до кода)

- **Маршруты** (`Admin/`, гардрил покрывает автоматом):
  `PATCH /api/admin/users/{id}` с `{is_active: bool}` (один update-путь,
  конвенция PATCH; пустое тело → 422 через `hasChanges`);
  `DELETE /api/admin/users/{id}` → 204.
- **Битый id в пути → 404** (frozen D4, не 400).
- **Идемпотентность:** повторный блок = 200 то же состояние, без 422-строки
  (PATCH-семантика; parity с promote невалиден — promote-роута нет).
- **Самоблок/самоудаление — запретить** (403, решение владельца).
- **Last-admin guard — строить** (решение владельца): `countByRole()`
  в порту + Doctrine; блок/удаление последнего активного админа → отказ.
  Наблюдение при реализации: пока стоит self-guard, last-admin недостижим
  по HTTP (actor-админ ≠ target-админ ⇒ счёт ≥ 2) — guard остаётся safety
  invariant с покрытием на юнит-уровне; функц. тесты честно проверяют
  приоритет self-guard. Восстановления без SQL нет (сидера/команды нет).
- **Fan-out в индекс при удалении** (решение владельца, против «оставить
  сироты»): reindex НЕ чистит (ItemReindexer:24-25, prune вне скоупа),
  сироты вечные; 6.5 чистит тот же каскад — чистим и здесь. Стоимость
  держит breaker 6.7. Сбор id **до** `remove()` (каскад отсоединяет).

## Скоуп

### 7.2a — сервис + порты + юнит (~1ч)

- `UserRepositoryInterface::countByRole(Role): int` + Doctrine
  (колонка `role` реальна, дёшево).
- `findIdsByOwnerId(OwnerId): list<string>` в портах Item и Collection
  + Doctrine (прецедент `findIdsByCollectionId`; offset-пагинация не нужна —
  только id, один запрос).
- `UserService::block/unblock/delete(User $target, User $actor)`:
  self-guard (actor == target → 403); last-admin guard (target — последний
  активный админ → 422); delete: сбор id → remove+flush → removeItem/
  removeCollection каждого.
- Юнит: порядок (id до remove), молчание port при упавшем flush,
  self → 403, последний админ → 422, ре-блок 200.

### 7.2b — контроллер + функц. + OpenAPI (~0.5ч)

- `Admin/UserController`: PATCH `{is_active}` + DELETE 204; id → 404.
- Функц.: блок/разблок/удаление админом; каскад в БД (коллекции ушли);
  документы убраны из индекса (поиск не находит); self → 403;
  последний админ → 422; 401/403 для чужих ролей.
- OpenAPI: два роута + схема `User` + frozen-списки.

## Карта ошибок

Чужой id → 404, гость → 401, не-админ → 403, битый id → 404 (D4),
пустое/битое тело → 422, self → 403, последний админ → 422.

## Вне скоупа

- 7.3 (создание админом), 7.4 (повышение) — переиспользуют гард и неймспейс.
- Prune-команда для сирот — отдельный триггер (6.4+6.5), не здесь.
