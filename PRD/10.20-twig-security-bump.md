# 10.20 — Security-бамп Twig `3.29.0` → `3.31.1`

## Дефект

`main` покраснел на блокирующем `Dependency Audit` после мержа #204 — не из-за кода, а из-за волны advisories Twig от 2026-11-24: **9 уязвимостей**, все закрыты в **`>=3.31.1`**.

Ключевые (семь из девяти — sandbox-обходы, требуют sandbox-политики и враждебного шаблона):

| CVE | Что ломает |
|-----|-----------|
| CVE-2026-133763 | sandbox `__toString()` bypass через `is true` |
| CVE-2026-133764 | sandbox `__toString()` bypass через входные custom-тесты |
| CVE-2026-133766 | sandbox `__toString()` bypass через spread-аргументы (с 3.28.0) |
| CVE-2026-133770 | sandboxed-шаблон переписывает `Markup` через конструктор |

Два advisories бьют и по приложениям без sandbox: **CVE-2026-133771** (escaper считает `x.attr` безопасным при импортированном макросе `x` → неэкранированный вывод; закрыт в 3.31.0) и **CVE-2026-133773** (неограниченный кеш конвертера `html_to_markdown` → рост памяти в долгоживущих воркерах; закрыт в 3.31.1, пакет `twig/markdown-extra`). Остальные — того же sandbox-семейства.

В проекте оба неприменимы: `render`/`renderView` в `src/` не вызываются ни разу, `twig/markdown-extra` не установлен. `templates/base.html.twig` — единственный шаблон, стоковый скаффолд, никем не рендерится; sandbox-конфигурации нет (`grep sandbox src/ config/` пуст).

## Решение

Только `composer.lock`: `composer update twig/twig twig/intl-extra --with-dependencies`. `composer.json` не меняется — констрейнт `"twig/twig": "^3.28"` уже допускает 3.31.1, поэтому правка констрейнта была бы шумом (и ослабила бы фиксацию версии).

Изменение lock: `twig/twig v3.29.0 → v3.31.1`, `twig/intl-extra v3.29.0 → v3.31.0`. Больше ничего не двигается — `--with-dependencies` подтянул только эти два пакета, что подтверждает diff по `"version"` (две пары строк, ни одного нового пакета).

## Почему это отдельная задача, а не часть 10.9

Тот же класс, что 10.17: внешняя волна advisories, наш код не при чём, PR трогает один lock-файл. Смешивать с функциональной задачей значило бы замаскировать security-правку в диффе 10.9 и закрыть гейт «попутно».

## Проверки

- `composer audit` — **No security vulnerability advisories found**.
- `composer show twig/twig` — `v3.31.1`.
- `ci:all` — полный прогон (гейты, phpstan, cs-fixer, rector, openapi-fresh, unit + coverage).
- `composer.json` в диффе отсутствует.

## Ограничения

Проверено только то, что Twig проходит наши тесты и аудит. Sandbox-пути в проекте не используются, поэтому поведенческая проверка исправлений сводится к «шаблоны фреймворка продолжают рендериться» — это покрыто существующими тестами, отдельных sandbox-тестов нет и заводить их нечего, пока нет пользовательских шаблонов.
