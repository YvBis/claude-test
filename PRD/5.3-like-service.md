# PRD 5.3 — Сервис лайков

## Статус

Выполнено (2026-09-16). Подзадача Этапа 5 (Социальное).

## Описание

`LikeService` — use-case слой над доменом `Like` (5.1): поставить лайк, снять, переключить, проверить состояние, посчитать лайки айтема и получить их список. Операции идемпотентны относительно пары (пользователь, айтем). Доступ (кто и к чему) — на уровне API (5.5); сервис правил доступа не содержит.

## Требования (артефакты)

- PRD: «ставить и смотреть лайки у айтемов», «менять свои лайки»; «Пользователь может поставить лайк айтему», «Пользователь может получить все лайки айтема»; «Администратор может удалить лайк любого пользователя».
- `Like`: UNIQUE `(owner_id, item_id)` — один лайк на пару.

## Решения (утверждены 2026-09-16)

- **Идемпотентность:** `like()` при существующем лайке возвращает существующий (не создаёт дубль); `unlike()` при отсутствии — no-op.
- **`toggle()` возвращает `bool`** — новое состояние (`true` = лайк стоит). Счётчик контроллер 5.5 собирает отдельно (`countByItem`).
- **`LikeDTO`** (id, owner_id, item_id, created_at) — контракт ответа на «получить все лайки айтема»; `implements ArrayableInterface` (memory #221).
- **`removeLike(Like)`** — отдельный метод под админское удаление (5.5/7.6).
- **Транзакции:** для одного агрегата достаточно `save`/`remove` + `uow->flush()` (как `ItemService::delete`); `transactional()` не нужен.
- **`LikeNotFoundException` не заводим** — при идемпотентности не требуется.
- **Гонка `like()`:** последовательность «найти → создать» при параллельных запросах может дать `UniqueConstraintViolation` (UNIQUE-индекс). Для MVP принимается, ошибку транслирует API. Кандидат в беклог — race-safe атомарный upsert (как `TagRepository::getOrCreate`).
- `OwnerId` получается из `User` (`OwnerId::fromBytes($user->getId()->toBytes())`), т.к. `LikeRepositoryInterface::findByOwnerAndItem` принимает `OwnerId`.

`src/Application/Like/Service/LikeService.php` (`final readonly`):

| Метод | Семантика |
|---|---|
| `like(User, Item): Like` | идемпотентно: есть — вернуть существующий; нет — `Like::create` + `save` + `flush` |
| `unlike(User, Item): void` | есть — `remove` + `flush`; нет — no-op |
| `toggle(User, Item): bool` | нет — поставить (`true`); есть — снять (`false`) |
| `isLikedBy(User, Item): bool` | для `liked_by_me` (5.5) |
| `getById(string): ?Like` | получить лайк по id (`null` — нет; контроллер 5.5 → 404); нужен админскому удалению, чтобы не тянуть репозиторий в контроллер |
| `countByItem(ItemId): int` | для `likes_count` (5.5) |
| `listByItem(ItemId, int $limit = 50, int $offset = 0): array<Like>` | список лайков айтема |
| `removeLike(Like): void` | админское удаление (5.5/7.6) |
| `toDTO(Like): LikeDTO` / `toDTOList(array<Like>): array<LikeDTO>` | контракт ответа |
