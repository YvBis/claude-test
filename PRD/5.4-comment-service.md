# PRD 5.4 — Сервис комментариев

## Статус

Выполнено (2026-09-16). Подзадача Этапа 5 (Социальное).

## Описание

`CommentService` — use-case слой над доменом `Comment` (5.2): оставить комментарий, получить его по id, изменить свой, удалить, получить список комментариев айтема и свои комментарии, посчитать их. Доступ (кто может менять/удалять) — на уровне API (5.5) и админки (7.6); сервис правил доступа не содержит.

## Требования (артефакты)

- PRD: «Пользователь может получить все комментарии айтема» (103), «Пользователь может оставить комментарий к айтему» (104), «Пользователь может поменять свой комментарий к айтему» (105), «Администратор может поменять или удалить комментарий любого пользователя» (117), «оставлять комментарии под своим именем» (56).
- `Comment`: `owner`/`item` — `ManyToOne` с `ON DELETE CASCADE`; UNIQUE нет (пользователь комментирует многократно); `content` — Markdown 1..3000.

## Решения (утверждены 2026-09-16)

- **Авторизация — в контроллере**, сервис не проверяет «свой/чужой» (конвенция: `ItemController::canAccess`).
- **Удаление своего комментария пользователем включено** (PRD 20 «менять свои комментарии»; админ-удаление — 117).
- **`CommentDTO` включает `owner_name`** (PRD 56 «под своим именем»; `owner` гидрируется JOIN FETCH в репозитории — без N+1).
- **`getById(string): ?Comment`** — без `CommentNotFoundException`; `null` контроллер 5.5 маппит в 404 (как `LikeService`).
- **`changeContent()` возвращает `Comment`** (для немедленного DTO); при нормализованно равном контенте сервис **не вызывает `save`/`flush`** (домен `changeContent` — no-op).
- **Имена методов:** `create` / `changeContent` / `delete` (по образцу `ItemService`).
- **Owner-чтения принимают `OwnerId`** (`listByOwner`, `countByOwner`) — симметрия с `ItemId`; конверсию `User → OwnerId` делает контроллер 5.5. `create(User, Item, string)` остаётся с `User` — он нужен `Comment::create`.
- **Транзакции:** для одного агрегата достаточно `save`/`remove` + `uow->flush()`; `transactional()` не нужен.
- **Валидация контента:** `CommentContent::fromString` бросает `\InvalidArgumentException` (пусто / >3000). **Для 5.5: невалидный контент → 422**, а не 404 (в `ItemController` `InvalidArgumentException` маппится в 404 для битого UUID — контент это другой случай).

### S2 — `CommentService` (~120 source / ~200 тестов)

`src/Application/Comment/Service/CommentService.php` (`final readonly`; ctor `CommentRepositoryInterface` + `UnitOfWorkInterface`):

| Метод | Семантика |
|---|---|
| `create(User, Item, string): Comment` | `CommentContent::fromString` → `Comment::create` → `save` + `flush` |
| `getById(string): ?Comment` | админский/редакторский путь; `null` → 404 в контроллере |
| `changeContent(Comment, string): Comment` | VO-сравнение до `save`/`flush` (no-op не флашит); возвращает aggregate |
| `delete(Comment): void` | `remove` + `flush` |
| `listByItem(ItemId, int $limit = 50, int $offset = 0): array<Comment>` | «все комментарии айтема» |
| `listByOwner(OwnerId, int $limit = 50, int $offset = 0): array<Comment>` | «мои комментарии» |
| `countByItem(ItemId): int` | счётчик для item-DTO (5.5) |
| `countByOwner(OwnerId): int` | счётчик «моих комментариев» |
| `toDTO(Comment): CommentDTO` / `toDTOList(array<Comment>): array<CommentDTO>` | контракт ответа |

`tests/Application/Comment/Service/CommentServiceTest.php` (моки репозитория/UoW): create + flush; невалидный контент (пусто / 3001) → `InvalidArgumentException`; getById найден/`null`; changeContent применяет + flush и возвращает aggregate; changeContent с тем же контентом — **без** `save`/`flush`; delete `remove` + flush; `listByItem`/`listByOwner` делегируют с пагинацией (проверка переданных `ItemId`/`OwnerId`); `countByItem`/`countByOwner`; `toDTO` (в т.ч. `owner_name`)/`toDTOList`.
