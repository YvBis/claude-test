# PRD: Task 4.2 — Сущность Tag и связующая таблица many-to-many

## Описание задачи
Доменная сущность `Tag` (глобальная, без владельца) с полями `id`, `name`, `created_at`, `updated_at`. Имя тега — отдельный VO `TagName` (нормализация + валидация). Связь «айтем ↔ тег» — many-to-many через связующую таблицу `item_tags`. Только Domain (сущность, VOs, интерфейс репозитория) + миграция; сервис тегов — отдельная задача 4.3, имплементация репозитория — тоже 4.3.

**Логика использования (реализуется в 4.3/4.4, здесь только инфраструктура):** при проставлении айтему тегов сервер по каждому имени нормализует его через `TagName`, ищет существующий тег (`findByName`, регистронезависимо); если найден — переиспользует, если нет — создаёт новый и привязывает.

## Решения, принятые из артефактов и согласованные с пользователем
- **Глобальные теги** — в доменной модели у `Tag` нет владельца; «переиспользовать существующий» работает между пользователями. UNIQUE на всю таблицу.
- **Регистронезависимая уникальность** — UNIQUE `name` + коллация `utf8mb4_0900_ai_ci` (`Books` = `books`). Хранится как введено; lookup через `=` (не `LOWER()`), чтобы не ломать индекс.
- **`TagName`** — VO `Embeddable`: trim + strip `\p{Cc}` + collapse whitespace + длина **2..30** + whitelist `[\p{L}\p{N} _\-\.\/]` (как `FieldName`).
- **Поля `Tag`**: `id` (binary 16), `name` (`TagName`), `created_at`, `updated_at` — по конвенции проекта.
- **Имя иммутабельно** — тег переиспользуется, не переименовывается; мутатора `rename` нет.
- **Связь M2M** — unidirectional `#[ORM\ManyToMany(targetEntity: Tag::class)]` на `Item` + `#[ORM\JoinTable(name: 'item_tags')]`. Join-таблица: `PK(item_id, tag_id)`, оба FK `ON DELETE CASCADE`.
- **Repository interface только** — `TagRepositoryInterface` (`save`, `remove`, `findById`, `findByName`); `DoctrineTagRepository` — в 4.3 (как `ItemRepositoryInterface` без имплементации в 4.1).
- **`fetch: 'LAZY'`** на M2M — загрузка по требованию; при необходимости JOIN FETCH `addSelect('tags')` в read-методах (паттерн ghost-proxy ORM 3).

## Ограничения
- Только Domain + migration + repository interface. Application/Infrastructure сверх интерфейса — нет.
- Doctrine ORM attributes (PHP 8), таблицы `tags` и `item_tags`.
- Class-level `#[ORM\UniqueConstraint]` / `#[ORM\Index]`, не в `#[ORM\Table(...)]`.
- VOs (`TagId`, `TagName`) — readonly, strict types; `TagId` через `UuidBinaryValue` (UUID v7).
- FK `item_id` → `items.id`, `tag_id` → `tags.id`, `binary(16)`, `ON DELETE CASCADE`.
- `DATETIME(6)` precision; миграция руками (не `schema:update`), с `COLLATE utf8mb4_0900_ai_ci` для соответствия golden reference baseline.
- Коллизия имён: доменный `App\Domain\Collection\Entity\Collection` vs `Doctrine\Common\Collections\Collection` → в `Item` алиас `DoctrineCollection`.
