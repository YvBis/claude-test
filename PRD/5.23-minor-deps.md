# PRD 5.23 — Миноры Doctrine/Twig/DAMA

Этап 5 (Социальное), review-задача. Отложено из 5.15: миноры с более высоким риском
изменения поведения, чем патчи. Плюс изучение changelog 3.7 и оценка новых фич
(нативная пагинация) — по требованию заказчика частью задачи.

## Находки

1. **Цели совпали с планом.** `doctrine/orm` 3.6.7 → 3.7.2,
   `doctrine/doctrine-bundle` 2.18.3 → 2.19.1,
   `doctrine/doctrine-migrations-bundle` 3.7.0 → 3.7.1,
   `dama/doctrine-test-bundle` 8.2.2 → 8.6.0, `twig/twig` 3.28.0 → 3.29.0,
   `twig/intl-extra` 3.26.0 → 3.29.0. Все шесть легли в существующие констрейнты
   (`^3.2`/`^2.12`/`^3.2`/`^8.2`/`^3.28`/`^3.26`).
2. **Транзитивный дрейф версий нулевой.** Dry-run и факт: сменились версии только
   шести целей плюс install `symfony/polyfill-php86` v1.41.0 (метаданные lock —
   констрейнты/время/хеши — шумят как обычно, версий не добавляют).
   `doctrine/collections` остался **2.6.0** — опасение senior-review (подъём на 3.x
   через `^2.2 || ^3.1`) не подтвердилось: точечный `composer update` без `-w`
   коллекции не тронул. Проверено заодно, что проект выдержал бы и 3.x:
   `Item.php:191` результат `->add()` не использует, подклассов `SqlValueVisitor` нет.
3. **`composer.json` тронут один раз — осознанно.** Добавлен
   `symfony/polyfill-php86: ^1.41` в `require`: после S2 наш код напрямую ссылается
   на `\SortDirection` (S2), поэтому транзитивной зависимости недостаточно.
   Триггер удаления: подъём platform.php на 8.6+ (нативный enum) — снять вместе
   с бампом PHP (5.25).
4. **15 мест со строковыми направлениями сортировки.** ORM 3.7 депрекейтит строки
   `'ASC'`/`'DESC'` в `QueryBuilder::orderBy()/addOrderBy()` (UPGRADE.md 3.7.x,
   «Deprecated using strings or null as sort directions»; замена — нативный enum
   `\SortDirection`, на PHP 8.3 — через полифилл). Без миграции — 15 новых
   депрекейшенов, которые заблокировали бы 5.25 (жёсткий `--fail-on-deprecation`).
   `#[ORM\OrderBy]` в маппингах нет, `Expr\OrderBy` напрямую не используется,
   подклассов `QueryBuilder` нет — BC-брейк по сигнатурам переопределений
   неприменим. Мигрировано все 15: CollectionField(1), Collection(2), Comment(4),
   Item(2), Like(4), Tag(1), User(1). Поведение не меняется — строки и enum дают
   идентичный SQL.
5. **Стиль: `\SortDirection` в FQ-форме.** Правило `global_namespace_import`
   из `@Symfony`-пресета php-cs-fixer требует глобальные классы в FQ-форме и
   удаляет `use SortDirection;` (`no_unused_imports` следом чистит). Это не
   противоречит конвенции проекта: неймспейсные enum'ы (`RoleEnum`, `ThemeEnum`,
   `FieldTypeEnum` из `App\...`) по-прежнему используются через `use` + короткую
   форму — правило касается только глобального неймспейса. UPGRADE.md пишет так же.
6. **PHPStan 1.12 полифилл-enum понимает.** Именованный риск не материализовался:
   `composer phpstan` — No errors.
7. **Перекос ORM/DBAL (новая находка).** `doctrine:schema:validate` и
   `doctrine:schema:update --dump-sql` падают в DB-sync половине с
   `[critical]`: `GenerateSchemaEventArgs::setSchema()` (новый код 3.7) требует
   DBAL API `Schema::edit()`, которого нет в DBAL 4.4.3 — «requires
   doctrine/dbal ^4.5». Стабильного DBAL 4.5 не существует (только 4.5.x-dev),
   поднять не на что. Mapping-половина — `[OK] The mapping files are correct`.
   `schema:validate` в CI не входит, поэтому PR не блокируется; фиксируется как
   известный upstream-перекос до выхода DBAL 4.5 stable.
8. **Недетерминированная сортировка (новая находка, не 3.7).** Только Like и Comment
   сортируют кортежем `(createdAt, id)`. Item (`DoctrineItemRepository.php:60,76`),
   Collection (`DoctrineCollectionRepository.php:56,69`) и Tag
   (`DoctrineTagRepository.php:93`) — по `createdAt`/`name` без id-тай-брейкера:
   строки с равными ключами могут перетасовываться между страницами. Меняет SQL —
   поэтому не в этом PR, а отдельной backlog-задачей (S5).

## Changelog 3.7: что не мешает

Проверено по UPGRADE.md 3.7.x и исходникам (ветка 3.7.x):

- `Tools\Pagination\Paginator` deprecated — в `src/` 0 использований.
- `#[ORM\JoinColumns]` deprecated — не используем.
- `LockMode::NONE` больше не рефрешит — мы lock вообще не передаём.
- `TypedExpression` deprecated — кастомных DQL-функций нет.
- `getEventManager()` — не вызываем.
- `doctrine-bundle` 2.19.x: `conflict: doctrine/orm <2.17 || >=4.0` — 3.7 проходит.
- `migrations-bundle` 3.7.1: `doctrine/orm ^2.6 || ^3` — проходит.
- DAMA 8.6.0: прямого ORM-констрейнта нет, bundle `^2.11.0 || ^3.0` — проходит.
- Бинарные UUID: в 3.7.0–3.7.2 нет изменений конверсии параметров — наш workaround
  (`->toBytes(), 'binary'`) остаётся необходимым.

## Новые фичи 3.7: оценка

- `OffsetPaginator`/`Window` — **ценности ноль при текущем контракте**: 8 list-эндпоинтов
  отдают голый массив без total/links; ценность пагинатора (`getTotalCount`,
  `hasNextPage`) требует смены контракта ответа. Если контракт когда-нибудь добавит
  total/навигацию — брать `OffsetPaginator`, не legacy `Paginator` (удаляется в 4.0).
- `CursorPaginator` — **непригоден без послойного решения** (разбор по исходникам
  3.7.x, commit `6b47a02c`):
  (а) `Cursor::encodeToString()` (`Cursor.php:73`) — голый `json_encode()` без
  `JSON_THROW_ON_ERROR`; сырые 16 байт UUIDv7 дают `false` → `(string) false` → `''` →
  пустой курсор. `CursorPaginator.php:166` трактует `''` как первую страницу —
  клиент получает `next_cursor: ""` и ходит по кругу первой страницы **без единой
  ошибки**. (Первоначальная формулировка «бросит JsonException» была неверна:
  на encode-флагов нет, бросает только decode-сторона через `InvalidCursor`.)
  (б) `CursorWalker.php:156` биндит предикат через `setParameter($name, $value)`
  без DBAL-типа → `ParameterTypeInferer` даёт `STRING`, а нужен `BINARY`.
  Для принятия понадобились бы hex/base64-слой сериализации и собственный биндинг —
  при том, что в репо **нет проблемы**, которую это решает: grep `cursor`/`keyset`/
  `slow` по Roadmap и AssumptionLog — 0 совпадений; лимит 1..100; этап 6 — поиск,
  не пагинация. Новой задачи не создаём. Триггер перепроверки: следующий минор
  ORM (если 3.7.3+ починит сериализацию/биндинг — вывод пересмотреть).
- `foreignKeyName` (JoinColumn/JoinTable) — опционально; наши FK-имена уже
  зафиксированы в миграциях.
- `setDefaultStringTypeSchemaLength()` — не нужно: у всех строковых колонок явный
  `length`, дефолт 255 не используется.
- `NULL`-литерал в DQL, `EntityRepository::expr()`, `#[Id(position:)]` — не нужны
  (нет кейсов: одиночные ID, `createQueryBuilder` устраивает).
- Native lazy objects для partial — требует PHP 8.4; у нас 8.3, **недоступно**.

## Решения

- Точечный `composer update <6 пакетов>` (без `-w`) + явный
  `composer require symfony/polyfill-php86`. Артефакты: `composer.json` (+1 строка),
  `composer.lock` (6 апдейтов + 1 install, транзитивных смен версий — ноль).
- Миграция 15 мест на `\SortDirection` **внутри 5.23** (иначе 15 депрекейшенов
  заблокируют 5.25). Отдельный PR не заводим: изменение поведение-нейтрально.
- `config/reference.php` (генерированный, трекается) откачен — дрейф от патчей 5.15,
  не от этой задачи.
- Проверки: `ci:all` 706/2095 exit 0, `coverage:gate` 97.74%, нативный
  `--display-deprecations` — 0 (сверено глазами, exit-гейта нет до 5.25),
  `lint:container` OK, `schema:validate --skip-sync` OK
  (DB-sync половина заблокирована перекосом ORM/DBAL — находка 7),
  `smoke515.sh` (`var/`, gitignored — в контейнер через `docker compose cp`) — 25/25, runtime `symfony-lsp` 0 diagnostics.
