# PRD: Task 3.1 — Сущность Collection

## Описание задачи
Создать доменную сущность `Collection` с полями: `id`, `owner_id`, `name`, `description`, `theme`, `image`, `created_at`, `updated_at`. Сущность должна находиться в `src/Domain/Collection/`. Владелец — `User` через ManyToOne.

## Ссылки на требования
- `artifacts/domain-model-taskflow-ru.md` — секция 1 "Сущности: Collection" (`id, owner_id, name, description, created_at, updated_at, theme, image`), секция 2 "Связи" (много коллекций → один User; одна коллекция → один User), секция 3 "Коллекция должна иметь владельца"; секция 4 "Темы коллекций" (Books/Games/Movies/Drinks)
- `artifacts/prd-taskflow-ru.md` — секция 5 ФР (CRUD коллекций владельцем)
- `artifacts/technical-requirements-taskflow-ru.md` — Clean Architecture (Domain layer), Doctrine ORM, строгие версии

## Решения, принятые из артефактов (агент фиксирует)
- **UUID `binary(16)` PK** — зеркалит User (миграция `users` использует тот же шаблон; `CollectionId` VO как у `UserId`)
- **Theme** — enum-backed VO (только `Books`, `Games`, `Movies`, `Drinks`). Список зафиксирован в `artifacts/domain-model-taskflow-ru.md §4`, жёстко в домене. Soft-validation типа `3.5` реализуется на уровне VO — отдельная сервисная валидация избыточна
- **`image`** — nullable string (путь/URL). Формат не уточнён в артефактах → минимум валидации (`#[Assert\Length(max: 500)]`)
- **`description`** — nullable text (`Types::TEXT`), без max длины (артефакт не ограничивает)
- **Repository и миграция — НЕ в этой задаче** — Task 3.2
- **Soft delete не используется** — `is_active` отсутствует в domain-model для Collection

## Ограничения
- **Только Domain слой** — никаких репозиториев, миграций, сервисов, контроллеров
- **Doctrine ORM attributes** (PHP 8 attributes), маппинг на таблицу `collections`
- **Value Objects**: `CollectionId`, `CollectionName`, `Theme` — readonly
- **Theme** — PHP 8.1 backed enum + VO-обёртка (симметрия с `App\Domain\User\ValueObject\Role`). Зеркалит маппинг `Role` через кастомный DBAL `ThemeEnumType` (как `RoleEnumType` в `src/Infrastructure/Doctrine/DBAL/Type/RoleEnumType.php`). Регистрируется в `config/packages/doctrine.yaml` под `types: 'theme'`. Колонка `theme` — `varchar(20)`. Коллекция конвертируется через `columnPrefix: false` ИЛИ через прямую колонку с `enumType` (см. реализацию — зеркалить `Role`)
- **Owner** через `ManyToOne` на `App\Domain\User\Entity\User` с `#[ORM\JoinColumn(nullable: false, onDelete: 'CASCADE')]`
- **FK `owner_id`** — `binary(16)` (миграция придёт в 3.2)
- **PSR-4**: `App\Domain\Collection\*`
- **Out of Domain**: `ThemeEnumType` живёт в `App\Infrastructure\Doctrine\DBAL\Type\` (не в Domain). Принимается как зависимость Theme VO через DI или статический адаптер — симметрия с `Role`

## Критерии приёмки
- [ ] VO классы в `src/Domain/Collection/ValueObject/`: `CollectionId`, `CollectionName`, `Theme`
- [ ] `Theme` принимает только `books`, `games`, `movies`, `drinks` (lowercase canonical, любой case-insensitive input нормализуется)
- [ ] `CollectionName` отклоняет пустую строку и >100 символов
- [ ] `Collection` Entity в `src/Domain/Collection/Entity/Collection.php`
- [ ] `owner_id` — `ManyToOne` на `User`, `nullable: false`, `onDelete: CASCADE`
- [ ] `theme` — `#[ORM\Embedded]`, маппится на колонку `theme`
