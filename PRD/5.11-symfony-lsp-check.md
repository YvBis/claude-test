# PRD 5.11 — Symfony-aware диагностика (`symfony-lsp check`) в CI и локально

> **Дополнено задачей 5.13 (2026-09-22).** Source-only пилот расширен до двух прогонов (source baseline + runtime с `--environment=test`), кэш покрывает архив и индекс с обязательной SHA256-проверкой на кэш-хите, скачивание получило retry с backoff и таймауты. Решение 5.11 «бинарник не кэшируем — восстановленный из кэша файл обошёл бы проверку SHA256» **отменено**: посылка была неточной (кэш-восстановление пропускало бы `curl`, а не проверку). Актуальный инвариант — «хеш проверен перед запуском»: архив проверяется на кэш-хите до распаковки, а бинарник всегда извлекается из проверенного архива. Решения ниже остаются историей; актуальное состояние — `PRD/5.13-symfony-lsp-runtime.md`.

Этап 5, инфраструктурная задача из периодического review (аспект «CI/инфраструктура»).
**Ни один файл `src/` не изменяется** — только CI, скрипты, конфиг и тест-обвязка.

## Цель

Добавить в пайплайн Symfony-aware диагностику, которой нет ни у PHPStan (типы), ни у PHP-CS-Fixer (стиль), ни у Rector (рефакторинг): маршруты, DI-контейнер, Twig, переводы, env-переменные, конфиги бандлов, Messenger, security, формы, валидация, Doctrine-метаданные.

Источник — `symfony/language-tools` (`symfony-lsp`, **v0.21.0**, релиз 2026-09-19). Это standalone-бинарник с подкомандой `check` (headless-режим) и выходами `human|json|github|gitlab|sarif`; коды выхода стабильны (`0` — ок, `10` — блокирующие находки, `11` — ошибка конфигурации/вызова, `12` — неполный анализ).

## Что НЕ входит

- **Runtime-режим в CI** — отдельная задача после пилота (нужны `.env`, JWT-ключи, MySQL/Redis; локально уже проверено, что работает). Зафиксировано как `5.13 [review]`.
- **Editor-LSP `symfony-lsp` в opencode** — на этой машине не подключаем: официальный гайд OpenCode ограничен Linux/Apple Silicon, а Windows-сборка (`windows-x64.zip`) не проверялась. PHP-редакторный LSP остаётся `phpantom`.
- **Baseline** (`.symfony-lsp-baseline.json`) — не нужен: активных блокирующих диагностик нет (source-only — 0; runtime — 1 warning, warning'и не блокируют).
- **Исправление найденной JWT-депрекейшн** — отдельная задача `5.12 [review]`, не в скоупе 5.11.
- **`fwd-11`** (политика `config/reference.php`) — не решается здесь; здесь только исключение файла из анализа.

## Проверки

```bash
# Локально (runtime, полный анализ; ~1 мин)
docker compose exec app composer ci:symfony-lsp

# Локально, статически (как в CI)
docker compose exec app composer ci:symfony-lsp -- --source-only

# Полный набор проекта (не изменяется, checker туда не входит)
docker compose exec app composer ci:all
```

## Риски

- **Пилот не блокирует** — намеренно: сначала неделя наблюдений, затем перевод в блокирующий и/или runtime-режим.
- **Сетевой доступ при установке** — версия закреплена, SHA256 проверяется; при недоступности GitHub job падает, но (пилот) не блокирует мерж.
- **`var/bin/`** — gitignored (`/var/`), не попадает в коммит.
- **Ложные срабатывания в будущем** — снижаются `excludePaths` и `--fail-on` (по умолчанию блокируют только error-severity).
