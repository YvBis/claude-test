# PRD — 7.3: создание пользователя админом

**Статус:** in progress (в `done` — только после мерджа)

**Оценка:** ~1.5ч (7.3a ~0.5ч, 7.3b ~1ч)

**User story:** artifacts/prd-taskflow-ru.md:64 — «как администратор, я хочу
иметь возможность добавлять новых пользователей вручную».

## Решения (зафиксированы до кода)

- **Маршрут:** `POST /api/admin/users` (`Admin/`, `IsGranted`, гардрил
  покрывает автоматом).
- **Тело:** новый `CreateUserDTO` в `App\Application\User\DTO` (рядом с
  `UserDTO`/`UpdateUserDTO`; `RegisterUserDTO` из `Application\DTO` —
  legacy-outlier, публичную регистрацию не трогаем): name, email,
  password + **опциональная `role`** с `Assert\Choice(Role::values())`.
  Без чойса мусорная роль дала бы 500 (Role::fromString кидает
  `InvalidArgumentException`), а не 422.
- **Роль при создании — опциональная** (решение владельца, против сплита
  7.3/7.4). Граница с 7.4 зафиксирована здесь: 7.3 минтит роль при
  создании, 7.4 — mutate существующего. Last-admin про удаление
  (7.2), симметричного инварианта на создании нет — счёт только растёт.
- **Путь сохранения:** `RegistrationService::register(dto, ?Role = null)`,
  дефолт сохраняет всех caller'ов. Один путь проверки email/хеша/flush.
- **Ответ:** 201 + `UserDTO` (токена нет — создание ≠ аутентификация).
  Дубликат → 409 тем же `conflict()`.

## Скоуп

### 7.3a — DTO + сервис + юнит (~0.5ч)

- `CreateUserDTO` (name/email/password + ?role с `Assert\Choice`).
- `RegistrationService::register(CreateUserDTO|RegisterUserDTO, ?Role)`:
  у сигнатуры два типа — принять решение по реализации (типизированный
  параметр или union), не ломая публичный путь.
- Юнит: роль по умолчанию user; админ-роль проставляется; мусорная роль
  отсекается DTO (422-путь покрыт через валидатор).

### 7.3b — контроллер + функц. + OpenAPI (~1ч)

- `Admin/UserController::create` → 201 + `UserDTO`.
- Функц.: админ создаёт, дубль → 409, юзер → 403, гость → 401,
  валидация → 422, мусорная роль → 422, созданный админ реально логинится
  под админским маршрутом.
- OpenAPI: роут + frozen-списки.

## Карта ошибок

Гость → 401, не-админ → 403, валидация/роль → 422, дубликат → 409,
битый JSON → 400. 404 не возникает (нет id).

## Вне скоупа

- 7.4 (повышение/понижение существующего) — mutate-путь, отдельная задача.
- Публичная регистрация не меняется.
