### 3. `DemoStoryTest`: assert пароля

Проверяется, что литерал `'password123'` проходит верификацию для `admin@example.com`
и `user01@example.com` (`PasswordHash::verify()`). Литерал захардкожен, а не взят из
`UserFactory::DEFAULT_PASSWORD`: иначе дрейф литерала при неизменном README остался
бы зелёным. Фабрика при этом может использовать константу — тест ловит расхождение
между кодом и документом.

### 4. CI smoke: пре-степ в job'е `e2e` после миграций

```yaml
- name: Seed demo data and smoke-test it
  run: |
    set -euo pipefail
    docker compose exec -T app php bin/console app:seed:demo --batch-size 500
    TOKEN=$(curl -fsS --max-time 30 -X POST http://127.0.0.1:8000/api/login \
      -H 'Content-Type: application/json' \
      -d '{"email":"admin@example.com","password":"password123"}' | jq -e -r .access_token)
    COLLS=$(curl -fsS --max-time 30 http://127.0.0.1:8000/api/collections -H "Authorization: Bearer $TOKEN")
    [ "$(echo "$COLLS" | jq 'length')" -ge 1 ]
    FIRST_ID=$(echo "$COLLS" | jq -er '.[0].id')
    [ "$(curl -fsS --max-time 30 http://127.0.0.1:8000/api/collections/$FIRST_ID/items \
      -H "Authorization: Bearer $TOKEN" | jq 'length')" -ge 1 ]
```

Детали, за которые уже заплачено ревью: `exec -T` (иначе «the input device is not a
TTY»), `set -euo pipefail`, `jq -e` на токен (иначе 401 деградирует в «0 коллекций»),
`jq -er` на id (иначе null даст 404), `--max-time 30`, комментарий про `APP_ENV=test`
из `.env`-копии (поэтому guard пропускает). Оба списка — bare array (OpenAPI).
DoD майлстоуна: seed exit 0 → JWT → коллекций ≥1 → айтемов ≥1.
