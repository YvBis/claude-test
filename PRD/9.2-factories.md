# 9.2 — Фабрики Foundry для шести сущностей

**Статус:** выполнено
**Ветка:** `task/9.2-factories`
**Родитель:** `Roadmap.md`, этап 9; зависит от 9.1 (стек установлен)

## Цель

Дать тестам и будущему сиду один способ строить доменные объекты: через
именованные конструкторы и VO, без ручного `new` в каждом тесте. Наполнение демо-данными
(Story, команда) — 9.3/9.4; здесь только инструмент и его доказательства.

## Решения

**D1. `PersistentObjectFactory`, а не `PersistentProxyObjectFactory`.** Первая попытка
на прокси-фабриках падает сразу: `Cannot generate lazy proxy: class "…User" is final`.
Все доменные сущности `final`, поэтому прокси-обёртка невозможна в принципе — это та же
причина, по которой репозитории делают `JOIN FETCH` вместо ленивых ассоциаций.

**D2. Свойства — аргументы конструктора, а не property-access.** У всех сущностей есть
публичный конструктор (`@internal … for test object creation`) с параметрами `id` + VO.
Фабрика передаёт VO напрямую: `Email::fromString()`, `PasswordHash::createFromPlain()`,
`CollectionName::fromString()`, `Theme::books()`, `CommentContent::fromString()`. Инварианты
домена выполняются, приватные поля не трогаются рефлексией.

**D3. Владение — не ассоциация (fwd-5), поэтому `ownerId` вычисляется, а не ссылается.**
`CollectionFactory`/`LikeFactory`/`CommentFactory` делают
`OwnerId::fromBytes(UserFactory::createOne()->getId()->toBytes())`. Ссылка на фабрику здесь
невозможна: Foundry попытался бы положить `User` туда, где конструктор ждёт `OwnerId`.
`\Closure` Foundry в аргументах конструктора **не** разворачивает (получали `Closure given`),
поэтому значение обёрнуто в `LazyValue`.

**D4. Владелец — `LazyValue`, иначе `defaults()` плодит мусорных пользователей.**
`defaults()` вычисляется **до** слияния атрибутов, поэтому жадное
`OwnerId::fromBytes(UserFactory::createOne()…)` создаёт одноразового пользователя даже тогда,
когда вызывающий передал `['ownerId' => $id]`. На сиде это 200 лишних аккаунтов.
`LazyValue::new(...)` разворачивается после подстановки overrides. Доказано красным: с жадным
значением `testPinnedOwnerDoesNotMintAThrowawayUser` падает.

**D5. Свободный текст — только из безопасных генераторов.** `Item::$name` и `TagName`
пропускают лишь буквы, цифры, пробел, `_ - . /`; `faker()->words()` и
`faker()->lexify('tag-??????')` остаются внутри whitelist, а `sentence()` — нет (для
комментариев допустимо: `CommentContent` сохраняет пунктуацию).

**D6. Старый `tests/Factory/UserFactory.php` заменён, а не оставлен рядом.** Он был мёртвым
кодом — `grep UserFactory` по `tests/` находил только само объявление, ни одного вызова.
Двух конвенций (`::create()` руками и Foundry) в проекте не будет.

## Доказательства

**Roundtrip.** В каждом тесте `EntityManager::clear()` между записью и чтением. Без `clear()`
проверялся бы identity map (PHP-объект в памяти), а не персистентность.

**Ассоциации — скалярным SQL.** После `clear()` `find(Item::class, …)` падает:
`Cannot generate lazy ghost: class "…Collection" is final` — ORM 3 не может построить прокси
для ленивой связи. Поэтому внешние ключи (`items.collection_id`, `likes.owner_id/item_id`)
читаются запросом, а сущность без ассоциаций (`User`, `Collection`, `Tag`, `Comment`) — через
`find()`. Это не обход проверки: строка с правильным FK доказывает то, что нужно, и без
прокси-магии.

**Хеш пароля мемоизирован.** `PasswordHash::createFromPlain()` всегда считает по доменной
константе `BCRYPT_COST = 13`; тестовая стоимость 4 из `security.yaml` относится к хешеру
фреймворка, а не к VO. Один хеш на процесс: иначе 50 пользователей в Story стоили бы ~20
секунд только на bcrypt. Замер: фабричные тесты 14.1 с → 7.8 с.

**Владелец ленивый.** `defaults()` считается до слияния атрибутов, поэтому жадный
`UserFactory::createOne()` внутри `defaults()` создавал бы мусорного пользователя даже при
переданном `['ownerId' => …]`. `LazyValue` это чинит; красное доказательство —
`testPinnedOwnerDoesNotMintAThrowawayUser` падает с жадным значением.

**DAMA × Foundry.** `FactoryRollbackProofTest` вставляет пользователя с фиксированным email
дважды — в двух последовательных тестах. Работающий откат даёт второму тесту чистую таблицу;
сломанный — падает на `UNIQUE`. Красное доказательство снято: при удалённом
`DAMA…PHPUnitExtension` второй тест красный. Два прогона подряд — зелёные.

## Грабли, стоившие времени (записано, чтобы не повторять)

1. **`taskflow_test` ≠ `taskflow`.** Тесты идут в `taskflow_test` (`.env.test` через
   `tests/bootstrap.php`), а `bin/console` по умолчанию — в `taskflow`. После красного
   доказательства с отключённой DAMA строки **закоммитились** в `taskflow_test`; чистка
   dev-базы их не убрала, и полный сьют падал на дубликате email и на «4 вместо 3».
   Лечение: чистить `taskflow_test` (`DATABASE_URL=…` явно), затем прогон.
2. **`repository()->count(['email' => …])` не работает**: `email` — embedded VO, а не поле.
   Считать надо DQL/DQB, а не критерием по имени свойства.
3. **Foundry не разворачивает `\Closure` в аргументах конструктора** — default-значения
   вычисляются сразу (см. D3).

## Что осталось за рамками

Слоты айтемов (`text_1…bool_3`) фабрика не заполняет: какие значения осмысленны — знание
демо-каталога 9.3. Теги к айтемам тоже добавляет Story, а не фабрика: `ItemFactory::createOne()`
даёт айтем без тегов, и это осознанный дефолт, а не пробел.
