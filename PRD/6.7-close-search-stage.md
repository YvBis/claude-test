## Скоуп

### A. review-10: circuit breaker (код, тройное ревью)

**Проблема:** с 6.4 движок в request path каждой мутации; fail-open
проглатывает ошибки, поэтому при мёртвом движке каждый вызов ждёт полный
транспортный таймаут (2 с, измерено в 6.4). Переименование/удаление
коллекции с N айтемами = N×2 с внутри одного запроса с итоговым 200
(N=500 ≈ 17 минут видимого успеха).

**Решение (senior-review плана, NEEDS-CHANGES принят):**
- Новый `WriteCircuitBreaker` (`src/Infrastructure/Search/`): после первой
  ошибки записи последующие пропускаются в течение TTL (дефолт 30 с,
  параметр `search.circuit_ttl_seconds` + env `SEARCH_CIRCUIT_TTL_SECONDS`).
- Семантика fail-open сохраняется (вызывающий видит успех), порт и сервисы
  не меняются; guarded — только writes, reads по-прежнему пробрасывают
  ошибки наружу.
- Отдельный мутабельный компонент, а не состояние в `final readonly`
  адаптере (readonly-класс не держит мутацию — проверено фаталом).
- Clock через `ClockInterface` для тестов (MockClock); в проде — фасад.

**Тесты:** `CircuitBreakerTest` (5 тестов, MockHttpClient + MockClock):
открытие цепи, пропуск внутри TTL, повторная проба после TTL, успех идёт
напрямую, reads не блокируются, delete тоже guarded.
