# PRD 5.30 — Один прогон PHPUnit вместо двух в CI

Статус: выполнено (2026-09-24). Строка Roadmap: 5.30.

## Проблема

Job `Unit Tests` шёл **608 с** (10:08), и половину этого времени съедал дублирующий прогон:

| Шаг | Время |
|---|---|
| Initialize containers | 36 с |
| Setup CI environment | 17 с |
| Run migrations | 6 с |
| `coverage:gate` | 272 с |
| отдельный advisory-прогон депрекейшенов | 269 с |
| остальное | ~8 с |

Второй прогон исполняет **те же 704 теста, на том же коде и той же БД** и не даёт нового сигнала: депрекейшены печатает тот же PHPUnit, а `--display-deprecations` не зависит от сбора покрытия. И покрытие здесь не узкое место: 272 с против 269 с — разница 3 с. Время съедают сами тесты, поэтому «второй прогон без покрытия» не дешевле первого.

## Решение

Один прогон вместо двух.

1. `composer.json`: `"phpunit": "XDEBUG_MODE=coverage phpunit --display-deprecations"`. Этот скрипт запускает `coverage:gate`, поэтому флаг получает именно тот прогон, который уже идёт в CI. Локальный `composer phpunit` тоже начинает показывать депрекейшены.
2. `.github/workflows/ci.yml`: второй шаг удалён; шаг покрытия становится `Run PHPUnit with coverage enforcement and deprecation reporting`.

Флаг живёт в composer-скрипте, а **не** передаётся как `composer coverage:gate -- --display-deprecations`. Второй вариант отклонён по замеру: composer дописывает дополнительные аргументы к **каждой** команде массива скриптов — зонд `composer probe -- EXTRA` на скрипте `["echo FIRST", "echo SECOND"]` напечатал `FIRST EXTRA` и `SECOND EXTRA`. То есть `coverage:gate` передал бы `--display-deprecations` и в PHPUnit, и в `php scripts/coverage-gate.php`.

### Shell-блок шага

```bash
set -o pipefail
status=0
composer coverage:gate 2>&1 | tee var/phpunit-ci.log || status=$?
if grep -qE 'triggered [0-9]+ deprecation' var/phpunit-ci.log; then
  echo "::warning::PHPUnit reported deprecations ..."
fi
cat var/phpunit-ci.log >> "$GITHUB_STEP_SUMMARY" || true
exit "$status"
```

- `pipefail` + сохранение статуса: падение тестов обязано ронять job (это coverage-гейт), но grep и step summary должны отработать и на падении — поэтому статус не теряется через `tee`.
- `continue-on-error` убран: единственная advisory-часть — строка депрекейшена, а сам шаг блокирующий.

## Почему не параллельные джобы

Параллельный второй джоб дал бы тот же wall-clock (`max(272, 269) + setup ≈ 330 с`), но ценой: второй раннер, вторая инициализация MySQL (~36 с), второй `composer install` (~17 с), дублирование миграций и **новое имя required-чека**, которое надо завести в `ci-summary.needs` + `STATUS` **и** в branch protection — иначе джоб молча выпадает из гейта (ровно дыра, которую закрывал 5.18). Слияние даёт ту же экономию без новой инфраструктуры и с одним required-чеком.

## Проверка

- Локально `composer coverage:gate` (слитый прогон): **705 тестов / 2073 ассерта**, покрытие **97.74%** (гейт ≥ 80.00%), 347.8 с.
- Негативная проба депрекейшена: временный тест с `trigger_error('probe', E_USER_DEPRECATED)` через **тот же shell-блок** → PHPUnit печатает `1 test triggered 1 deprecation`, grep срабатывает, `status=0` (job остаётся зелёным). Временные файлы удалены.
- Негативная проба падения: временный падающий тест → `status=1`, grep не срабатывает, то есть падение доходит до гейта сквозь `tee`.
- Guard-тест `DeprecationConfigTest` — 4 теста / 45 ассертов: **ровно один** запуск suite в джобе, `--display-deprecations` в composer-скрипте `phpunit`, `--no-coverage` отсутствует, `continue-on-error` отсутствует, grep + step summary на месте, bridge-env по-прежнему нигде не используется.
- Ожидаемое время джобы на раннере: **~340 с вместо 608 с**; фактическое измерение — прогон CI самого PR. **Факт (CI run `36012715211`, PR #89): job `Unit Tests` — 365 с вместо 608 с**, из них шаг прогона 328 с; экономия **243 с** (~4 мин). Проекция оказалась чуть оптимистичной: шаг прогона занял 328 с против 272 с у прежнего coverage-прохода (добавка `tee`, `mkdir`, грепа и разброс раннера), а инициализация контейнеров в этом прогоне была быстрее (19 с против 36 с).

## Остаточный риск

Депрекейшены теперь наблюдаются только под `XDEBUG_MODE=coverage`. На регистрацию депрекейшенов xdebug не влияет (проверено пробой), но если появится тест, ведущий себя по-разному под xdebug, это заметит только coverage-прогон. Риск принят осознанно, а строка 5.25 (мажорный свип) уже требует перепроверить, что оба флага не деградировали при переходе на PHPUnit 12. Отдельно отмечено ревью: регулярка грепа привязана к формулировке вывода PHPUnit, поэтому её дрейф должен ловить runtime-зонд — строка 5.31.

Альтернативы (pcov, шардинг, paratest) не рассматривались: они меняют инструмент сбора покрытия или структуру suite и заслуживают отдельной задачи.

## Не входит в задачу

- Жёсткий гейт `--fail-on-deprecation` — задача 5.25 (после 5.30 это один флаг на единственном прогоне).
- Ускорение самого прогона (pcov, шардинг, paratest).
