## Гипотезы (фиксируются до кода, все измерены на теге v3.2.0)

- H1. Удаления 3.0 нас не цепляют (`UPGRADE-3.0.md`): Guard-`JWTTokenAuthenticator`,
  `DefaultJWTEncoder` (+сервис), `DefaultJWSProvider`, `OpenSSLKeyLoader`
  (+сервис), `JWTManagerInterface`, `setUserIdentityField`,
  `loadUserByUsernameAndPayload`. Мы не используем ни одного:
  firewall `api` — `jwt: ~` (`security.yaml:17-21`), не Guard.
- H2. Наш конфиг (`lexik_jwt_authentication.yaml:1-8`: secret_key,
  public_key, pass_phrase, token_ttl, clock_skew,
  encoder.signature_algorithm) — все шесть ключей живы
  в `Configuration.php` вендора 3.2.0. Удалённые `private_key_path`,
  `public_key_path`, `encoder.crypto_engine`, `user_identity_field`
  нами не использовались. Конфиг не меняется.
- H3. `Services\JWTManager` существует на v3.2.0 и реализует
  `JWTTokenManagerInterface`; `createFromPayload(UserInterface, array):
  string` — байт-в-байт вызов в `UnauthorizedEnvelopeTest.php:63`.
  `assertInstanceOf(JWTManager::class)` остаётся валиден.
- H4. `UserProvider` реализует только `UserProviderInterface`
  (`loadUserByIdentifier`); смена `PayloadAwareUserProviderInterface`
  (`loadUserByUsernameAndPayload` → `loadUserByIdentifierAndPayload`)
  его не касается.
- H5. `lcobucci/jwt` 5.6.0 уже удовлетворяет `^5.0` (требование 3.2);
  подъём `^4 → ^5` случился до нас. `symfony/* ^7.0` + `extra.symfony.require
  7.*` запрещают прыжок на Symfony 8 при `-W`. Ожидаемый дифф lock:
  lexik 2.21.0→3.2.x, удаление `namshi/jose ^7.2` (только для v2),
  возможен бум `lcobucci/clock`. Транзитивных мажоров нет.
- H6. Пин: `"lexik/jwt-authentication-bundle": "^3.2"` (диапазон —
  конвенция `require`; точные пины — только `require-dev`).
  `lcobucci/jwt: "*" → "^5.0"` в том же PR (прямая связь с бампом,
  `*` прячет реальный пол).

## Измерения по ходу

- **Срез A: список падений — 5 errors + 14 failures (20 тестов 401).**
  Разбор дал два разных корня. (1) Stale-контейнер: первая проба шла
  через контейнер lexik 2 (6 аргументов с `'openssl'` против 5 в v3) —
  закрыто `cache:clear`, свежий контейнер вирит
  `(keyLoader, 'RS256', 3600, 0, false)` корректно. Урок: после мажора
  бандла чистить кэш до первого прогона, иначе чинишь призраков.
  (2) Настоящие 3 errors: `AuthenticationFailureEvent::$exception`
  в v3 типизировано non-nullable, а тест строил событие с `null`.
- **Срез B: фикс — реальные исключения вместо `null`.** Провайдер
  отдаёт `MissingTokenException` / `InvalidTokenException` /
  `ExpiredTokenException` как в продакшен-`JWTAuthenticator`.
  Итог: `OK (20/58)`, конверт 401 неизменен (статус + 3 текста +
  заголовок).
