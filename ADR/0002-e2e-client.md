# ADR-0002 — Клиент E2E-тестирования для TaskFlow

- **Статус:** принято 2026-10-13, задача `8.1`
- **Заменить, если:** см. «Что заставит пересмотреть»
- **Связано с:** `PRD/8.1-e2e-bruno.md`, `Roadmap.md` (Этап 8)

## Контекст

Проект — REST API без фронтенда. Функциональные тесты ходят в ядро через `WebTestCase` и
**не пересекают nginx/php-fpm**: маршрутизация, параметры fastcgi, коды ответов настоящего
HTTP-стека остаются непроверенными (то же замечание в `PRD/8.1-e2e-bruno.md`). Задача 8.1 —
закрыть этот слой сквозными пользовательскими путями против **собранного** стека.

Требования к инструменту: headless-прогон в GitHub Actions, коллекция в git (диффабельна,
ревьюится в PR), отсутствие обязательного облачного аккаунта, ассерты статуса/полей и
проброс значений (token, id) между запросами, minimum нового тулчейна.

## Решение

Использовать **Bruno** (`@usebruno/cli`), коллекция — plain-text `.bru` в `tests/E2E/`.

Проверенные факты (доки 2026, не память): `bru run` возвращает non-zero при падении
ассерта; коллекция — офлайн-файлы, облако не требуется; цепочки — `bru.setVar(...)` /
`{{var}}`; секреты — через `--env-var` (у нас их нет — только тестовые константы).

## Отвергнутые варианты

| Инструмент | Почему нет |
|---|---|
| **shell + curl** | нет декларативных ассертов: каждый статус/поле парсится руками (`jq -e`), цепочки — самописная bash-обвязка, которую поддерживаем мы |
| **Postman / Newman** | коллекция JSON 2.1 шумная в диффе; раскол авторство (v3 YAML) против раннера (v2.1); Free-план — 1 пользователь, ревью коллекции командой упирается в платный Team |
| **Insomnia / inso** | git-YAML, но метаданные пачкают диффы; exit-код при падении именно ассерта (а не статуса) задокументирован тонко |
| **Apidog** | истина в облаке, обязательный аккаунт в CI — нарушает git-native и no-cloud |
| **HTTPie** | не раннер: одиночные запросы удобны, но E2E — самописный bash+jq-харнесс (и то же возражение, что к shell) |
| **Playwright** | браузерная автоматизация для UI, которого нет; тянет Node + браузерные бинарники ради голого HTTP |
| **`macarthy/bruno-mcp`** | MCP-генератор `.bru` (не запуск): 35 звёзд/3 коммита, генерирует то, что и так пишется напрямую; MCP-клиента в проекте нет |

Node — цена решения; он ограничен шагом CI и локальным запуском, `package.json` в репозиторий
не входит, поэтому связка остаётся поверхностной.

## Последствия

- Версия `@usebruno/cli` **пинуется** в CI (`4.2.1`): `.bru` и флаги версионно-чувствительны, а
  job блокирующий — незаявленный релиз апстрима не должен его ломать (та же дисциплина, что у
  `symfony-lsp` и `meilisearch`).
- Стек в CI идёт с `APP_ENV=test` (`.env` — копия `.env.test`): это честный HTTP-путь, но не
  прод-конфиг.
- Redis в compose-стеке не задействован сценариями (нет `cache.app`-потребителя в `src`,
  messenger под `when@test` — `in-memory://`) — в текстах покрытия его не заявляем.
- Задача 8.2 (smoke) переиспользует этот же инструмент: `tests/E2E/smoke/` (register → login →
  свои айтемы → гостевой поиск → admin-403), локальный запуск `bru run smoke --env local`, без
  CI-проводки. Shell+curl для smoke отвергнут повторно — второй харнесс ради статус-проб ценой
  единообразия не окупается, раз Node разработчикам всё равно нужен для e2e (решение —
  `PRD/8.2-smoke-bruno.md`).

## Что заставит пересмотреть

- Появление фронтенда → нужен браузерный E2E (Playwright и подобные) в репозитории фронтенда;
  этот ADR описывает только API-путь и не мешает ему.
- Bruno перестаёт быть офлайн/git-native либо вводит обязательный аккаунт для CLI.
- Node-тулчейн в CI становится источником регулярных поломок (тогда — shell+curl как
  деградация с явной потерей декларативных ассертов).
